# 項目一（主要）：量具料號統一到「採購料號」
## 使用者定案（2026-07-30，請勿自行改方向）
- **不要另建量具規格主檔**。量具的規格要**掛到採購料號**（`purchase_item` → `purchase_spec`），理由：全公司料號只留「採購料號」與「產品料號」兩種比較單純，且**入庫未領的量具也要查得到**。
- 同規格同廠牌會有多支實體，所以**實體仍以量具編號（`qc_tool.Tool_No`）為主**，再往上指向規格。
- **校驗週期維持「依類別設定」**（現行 `bulk_set_cycle`），這次不要改成依規格帶入。
- 68 筆舊資料：**自動解析編號括號內容產生草稿，使用者確認後才寫入**（不可直接寫）。

## 現況資料
- `qc_tool`：68 支實體量具，`Tool_No` 例：`A-001-Q (0-25mm)`、`A-200-Q 電子(0-25mm)`、`B-003 (0-600mm)`；規格是人工塞在字串裡。
- `qc_tool_list`：18 個類別（游標卡尺／盤式分厘卡／缸徑規…）。
- `purchase_item`（item_id, item_code, category_id, item_name, default_unit_id, default_vendor_id…）／`purchase_spec`（spec_id, item_id, spec_code, spec_text, attr_json, unit_id, location_id, safety_qty…）目前**都還沒有資料**，欄位語意請先讀 `src/common/purchase_lib.php` 確認（尤其 `item_code`／`spec_code` 的產生規則與 `category_id` 是否必填）。

## 要做的事
1. **`qc_tool` 加欄**（只加不改）：`purchase_spec_id INT NULL COMMENT '對應採購料號規格 purchase_spec.spec_id'`，加在 `tool_calib_ensure_schema()` 的 ALTER 清單。
2. **解析草稿產生器**（新 action，例 `spec_draft`，管理員）：把每支量具的 `Tool_No` 解析成
   `類別（＝qc_tool_list.QC_Tool，當成 purchase_item 的品項）` ＋ `規格文字（括號內，例 0-25mm）` ＋ `型式（編號中出現「電子」→ 電子，否則機械）`；廠牌無法從編號得知，**留空待使用者補**。
   - 半形/全形括號都要處理（現有資料有 `B-007-Q (0-300mm）` 這種混用）。
   - 回傳草稿列表供前端表格編輯（可改品項名／規格文字／廠牌／型號）。
3. **確認後寫入**（新 action，例 `spec_apply`，管理員、transaction）：
   - 依草稿在 `purchase_item` 建立品項（同名沿用既有、不重複建），在 `purchase_spec` 建立規格（同 item＋同 spec_text 沿用既有）。
   - 回填 `qc_tool.purchase_spec_id`。
   - 回報：新建品項數／規格數／綁定量具數。
4. **UI**：放在「設定」跳窗（`cfgMask`）新增一個分頁「量具料號對應」——上方按「產生草稿」，中間可編輯表格，下方「確認並建立料號」。**不要再往工具列加按鈕**（使用者已明確要求整體設定都收在 cfgMask）。
5. **清單顯示**：量具清單「類別」欄旁可加顯示規格（`spec_text`），未綁定者顯示「未對應料號」。
6. **不要做**：不要新增第三套料號、不要改 `Tool_No` 既有值、不要動線上檢驗頁對 `qc_tool` 的既有使用。

## 驗收
- 68 支量具都能產出草稿且不重複建品項／規格；重跑草稿不會重複寫入。
- `qc_tool` 既有欄位與 `Tool_No` 未被更動（`git diff` 與 SQL 抽查各一次）。
- 線上檢驗（`inspection_combined_prototype.php`）的量具下拉與檢驗登錄仍正常。
