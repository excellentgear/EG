# 教育訓練管理 模組說明（交接文件）

> 用途：本文件供其他 AI／工程師接手修改「教育訓練管理」頁面時閱讀。內含完整檔案、資料表、API、UI、KPI、已完成/待做、與**必須遵守的專案慣例**。
> 對應 KPI：2-GM-04-01 第 19 項「人員教育訓練達成率」。最後更新：2026-07-29。

---

## 1. 模組概述
- 頁面：`views/ADM/training_record.php`（教育訓練計畫與執行管理）。
- 目的：管理各部門/年度的教育訓練「場次」（計畫→實際開課），並作為 KPI #19 的資料來源。
- KPI #19 口徑＝**場次**：達成率 = 當月「已完成(done)」場次 ÷「計畫(排除取消)」場次；依 `plan_month`（計畫月份）歸月。
- 場次分「內訓」（有講師）與「外訓」（不需講師，填開課單位）。
- **作業三階段（2026-07-29 定案）**：`計畫`（要辦什麼）→ `確認實行`＝**確定要開這堂課**（登開課日期/時段/地點/參加人員，狀態轉 `scheduled` 已排定，此時就能印簽到表給人員簽名）→ `登錄完成`（上完課勾實到，狀態轉 `done` 才計入 KPI）。**「確認實行」不是上完課才按**，這是使用者明確定義的語意。

### 班別（休息時間來源）
- **不自建班別表**，直接用輪值排班的 `shift_type`（`views/pages/roster.php` 的固定班別設定畫面維護）：`start_time`/`end_time`/`break_minutes`。
- 讀取用 `training_shifts($db)`（只列 `is_active=1`）。選了班別＝把上下班時間與休息分鐘帶入「每日上課時間」批次欄並套用到全部日期。
- **上下班時間只是開課時間的參考值，不限制上課時間必須落在該區間內**（使用者明確要求，勿加這個驗證）。

## 4. API（`src/store/Training_API.php`，action 參數）
| action | 方法 | 參數 | 回傳/作用 |
|---|---|---|---|
| meta | GET | — | perms、departments、years、**locations(地點主檔)**、cur_year、cur_month、today |
| list | GET | year | 該年所有場次（含 dept_name）＋各月/年度達成率 summary |
| people | GET | dept_id | 該部門人員 [{id, user_cname, position_name}]（講師/參加人員選擇用）。**已排除離職(state=0)、共用帳號(is_shared_account=1)、系統/公用身分(user_status 9/90/9999)**；職稱取該部門 is_main 優先的 position.name |
| get_attendees | GET | session_id | 該場次參加名單 |
| save_session | POST | 見下 | 新增/修改**計畫**；回 session_id（**不動狀態與實行欄位**） |
| save_execution | POST | session_id, **days(JSON)**, location, shift_type_id, mark_done(0/1) | 寫上課日期明細/地點/班別（**不動計畫欄位**）。mark_done=1→`done`；否則推進到 `scheduled`（原本已 done 者維持 done）。已取消的場次會擋下。days 逐筆驗證並回傳可讀原因（日期不存在/重複、時刻 0-23:0-59、同日結束不可早於或等於開始、休息 0~480 且不可 ≥ 上課時間、時數 0~24），全部通過才寫入。**寫完自動呼叫 `training_event_sync()` 同步行事曆**，回傳 `events`＝寫入事件數 |
| save_location | POST | name | 新增上課地點到主檔（已存在則恢復啟用）；回傳最新 locations |
| del_location | POST | loc_id | 停用地點（is_active=0，**限訓練管理員**）；回傳最新 locations |
| set_status | POST | session_id, status(planned/cancelled) | 取消計畫 / 恢復計畫 / 退回計畫中；一律把 done_date 清空、**撤除已同步的行事曆事件**（時段/地點/休息/實際時數/名單保留） |
| save_settings | POST | default_shift_id, cat_internal, cat_external | 模組設定（**限訓練管理員**）；回傳最新 settings 與實際生效的類別 id |
| save_attendees | POST | session_id, attendees(JSON) | 整批取代名單；**同步 target/actual_headcount**；保留既有 signed 狀態 |
| copy_session | POST | session_id | 複製內容為新的**計畫中**場次，**不帶名單**（供分場次）；回新 session_id |
| delete_session | POST | session_id | 刪場次（連帶刪名單）；管理員 |

- save_session 參數：session_id(0=新增)、year、plan_month、dept_id、course_name、train_type、trainer、trainer_id、org_unit、hours、note。
  - train_type=external 時後端會清空 trainer/trainer_id 並強制要求 org_unit；internal 時清空 org_unit。
  - **不接受 status/done_date/start_time/end_time/location**（避免編輯計畫時洗掉已登錄的實行紀錄）；新增時 status 固定 `planned`。
- **狀態流轉**：`planned` --save_execution(mark_done=0)--> `scheduled` --save_execution(mark_done=1)--> `done`（planned 也可一次直接 done）；`scheduled`/`done` --set_status(planned)--> `planned`（退回）；`planned` --set_status(cancelled)--> `cancelled`（可再恢復）。**已排定/已完成的場次不提供直接取消**，須先退回計畫中。
- attendees JSON 格式：`[{user_id, user_name, dept_name, position_name, attended(0/1)}, ...]`。

## 5. 權限（RBAC，module='training'，fail-closed）
- 角色：`training_view`(訓練檢閱)、`training_edit`(訓練登錄)、`training_admin`(訓練管理員)；能力階層 admin⊃edit⊃view。
- 系統管理者（user_status 9/90 或系統 admin 角色）固定全權。
- 權限判斷在 `training_lib.php` `training_perms()`；指派於「使用者權限設定」頁（prefix train）。

## 6. UI 結構（training_record.php）
- **工具列**：年度、部門、狀態、搜尋、新增訓練場次(btnAdd)、**模組設定(btnSetting，限訓練管理員)**、匯出CSV、列印、角色徽章。
- **統計條**：年度達成率 + 12 月各月達成率 pill（<95% 紅字）。
- **清單表**：月份｜對象部門｜課程名稱｜類型(內/外訓)｜講師/開課單位｜時數｜應到｜實到｜狀態｜實際開課日｜操作。
  - 操作欄依狀態變化：`planned`＝計畫｜確認實行｜取消｜複製；`scheduled`＝計畫｜實行資料｜複製；`done`＝計畫｜實行紀錄｜複製；`cancelled`＝計畫｜恢復｜複製；管理員另有刪除。
  - 時數欄顯示 `actual_hours`（沒有才顯示計畫 `hours`），與計畫不同時加紅色 `*` 並在 title 標出兩個值。
- **計畫與實行分兩個跳窗（2026-07-29 改版，重要）**：計畫 modal 只填「要辦什麼」，日期時間／地點／參加人員一律在確認實行 modal 才填。兩個 modal 打各自的 API，互不覆寫。
- **計畫 modal**（id=edMask）：年度、計畫月份、課程名稱、對象部門、訓練類型(edType)、**預計天數(edDays)**、預計總時數(edHours)、講師或開課單位、備註。天數/時數即時驗證（`edValidate()`），多天會提示平均每天時數。
  - 內訓區(edInternalBox)：講師 = 部門(edTrainerDept)→人員(edTrainerPerson) 下拉帶入文字(edTrainer)，也可直接打字（外部講師）。
  - 外訓區(edExternalBox)：開課單位(edOrgUnit)。切換由 `applyType()` 控制顯示。
  - 送出 `submitEd()` → save_session。**此 modal 已無狀態、實際開課日、時段、地點、名單欄位**，改計畫不會影響已登錄的實行紀錄。
- **確認實行 modal**（id=exMask，class wide；`openEx(sid)` 開啟，來源列存於 JS 變數 `EXROW`）：
  - 上方 `#exPlanInfo` 唯讀顯示計畫摘要（課程/狀態/年月/部門/類型/講師或單位/計畫時數）。
  - 可填：開課首日(exDone)、上課天數(exDays)、上課地點(exLocSel＋「地點設定」按鈕)、**套用班別(exShift)**、每日上課時間批次欄(exBStart/exBEnd/**exBBreak 休息分鐘**)、**上課日期明細表**(dayBody，每天一列：日期/開始/結束/**休息(分)**/時數/檢查/刪除)。
  - **時數＝(結束−開始)−休息**（`calcDayHours()`）：選班別會把該班別的上下班時間與 `break_minutes` 帶入並套用到全部日期；休息與時數都可逐日手改。休息 ≥ 上課時間時即時報「上課時間 X 分鐘不足以扣除休息 Y 分鐘」。
  - **時間欄一律是可手打的 text**（`parseTime()` 接受 `09:00`/`0900`/`900`/`9`/全形冒號，離開欄位才正規化）——使用者 2026-07-30 明確退回下拉選時間的做法，**勿改回下拉或 `input type=time`**。
  - **即時驗證**（`dayValidate()` 每次輸入就跑）：日期存在/不重複、時刻 0-23:0-59（擋 `25:00`）、同日結束不可早於或等於開始、當日時數 0~24；錯誤欄位加 `.inv` 紅框、該列「檢查」欄顯示原因，正確則顯示 `✓ 09:00~12:00`。送出前再跑一次，不通過會把第一個原因（`DAY_ERR`）顯示出來。
  - **多天流程**（使用者要求「可以直接全部設定後部份修改」）：`dayRebuild()` 依首日＋天數排連續日期；`dayApplyAll()` 把批次時間套到全部日期（不動日期）；之後可逐列改日期/時間/時數、`dayAdd()`/`dayDel()` 增減；改首日會整段日期一起平移。
  - 時數：有起訖就自動回填當日時數（可手改扣午休）；`#exTotalHint` 顯示各天合計，與計畫總時數不同時 `#exHourHint` 紅字提示。實際總時數存 `actual_hours`，計畫 `hours` 不動。
  - **參加人員名單**：部門(attDept)→載入人員 checkbox(attPeopleBox，顯示「姓名（職稱）」)→「加入勾選人員」進名單；名單表(attBody)含姓名/部門/**職稱**/實到 checkbox/簽名狀態/移除。名單存於 JS 變數 `ATT`。
  - 送出 `submitEx(markDone)` → 先 save_execution 再 save_attendees（同步人數）。footer 兩顆主鈕：**確認開課/儲存**(markDone=0) 與 **登錄完成**(markDone=1，會二次確認)；已完成時隱藏「登錄完成」。
  - 已排定/已完成的場次顯示「退回計畫中」(`revertPlanned()` → set_status)。
  - 「列印簽到表」按鈕 = `printSignSheet()`，資料取自 `EXROW`＋`DAYS`＋exLocSel＋`ATT`，開新視窗印 A4 簽到表（欄位：序/姓名/部門/職稱/簽名/時數確認；日期列格式固定為 `日期：2026-06-10  14:00~15:20`）。**多天課程＝一天一頁**（`.pg+.pg{page-break-before:always}`，標題含「第 N / M 天」），因為每天都要各自簽名。
- 複製場次：清單「複製」= `copySession()` 呼叫 copy_session。取消/恢復 = `setStatus(sid, status)`。

## 6-2. 行事曆同步（`training_lib.php`：`training_event_sync` / `training_event_remove`）
- **時機**：狀態變成 `scheduled`（確認開課）或 `done` 時自動寫入；退回計畫中 / 取消 / 刪除場次時自動撤除。改期後重存＝先移除舊事件再重建（不會殘留舊日期）。
- **一個上課日一筆 `evenement`**：`title`＝`教育訓練：課程名稱（第N/M天）`、`start`/`end`＝該日日期＋起訖（沒填時間則 `allday=1`）、`category_id`＝依內/外訓綁定、`remark`＝內外訓／講師或開課單位／對象部門／地點／時數／`（教育訓練管理 #場次id）`。
- **可見對象**：`evenement_target` 寫 `all` ＋ `evenement_recipient_cache` 展開全體在職者（教育訓練屬公司事務）。寫法比照 `src/store/_events_setting.php` 與 `leave_lib.php`。內訓且有 `trainer_id` 時另寫 `evenement_actor`（講師）。
- **事件 id 記在 `training_session_day.evenement_id`**，撤除只刪這些 id 指到的事件，**不用條件反查**（避免誤刪他人事件）。
- 同步失敗（例如未綁定類別）一律不擋存檔，前端會提示「未寫入行事曆：請於模組設定綁定行事曆類別」。

## 7. KPI 計算（training_lib.php `training_kpi_compute`）
- den = 該年月 plan_month 的計畫場次（status<>'cancelled'；參數 include_cancelled=1 則含取消）。
- num = 其中 status='done' 場次。
- value = den>0 ? num/den*100 : null。
- 已於 `kpi_as_lib.php` registry key `training_completion` 註冊；指標 #19 source_mode=auto。
