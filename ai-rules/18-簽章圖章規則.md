# 18. 簽章一律用「圖章」（全站表單／列印文件通用）

> 2026-08-13（三次，最終定案，取代前兩次關於圖章尺寸的補充）：`review_form.php` 圖章「感覺很小」這個問題前後修了四輪才真正解決，最終做法跟前兩次補充寫的都不一樣，**這裡是唯一有效的定案版本，第6/8條已改寫，前兩次補充內容作廢勿參考**：
> - **真正根因不是尺寸公式算錯，是「整頁自動縮小塞進一頁」（`document.body.style.zoom`）跟圖章的「固定尺寸」需求天生互斥**。圖章一旦維持真實尺寸，會撐大所在儲存格，讓實際內容高度跟原本算縮放比例時的高度對不上，造成縮放比例沒抓對、圖章仍被殘留縮小——這個現象在同一份文件上實測了三次都印證：換算成94.5px後仍縮成1.4cm、加上反向補償(`el.style.zoom=1/zr`)仍縮成1.9cm、改用`position:fixed`逃脫縮放的圖層技巧同樣沒有徹底解決。
> - **最終解法：`egPrintWindow()` 直接拿掉 `document.body.style.zoom` 整頁縮放邏輯**，改成比照 `training_record.php`／`ai-rules` 的 print_pagination 鐵則既有作法——分頁 100% 交給瀏覽器列印引擎原生處理，內容略超過一頁時自然分成第2頁，不再強行壓縮成一頁。圖章從此完全不會被任何縮放邏輯碰到。表格若常常剛好超過一頁，正確做法是**從一開始就把字級/欄位留白設計得收斂一點**（例：`review_form.php` 最終定案 12px 字級、6px7px padding），而不是印的時候再用 JS 硬壓。
> - **圖章尺寸 CSS 直接比照 `training_record.php` 已驗證過的寫法**，不再堅持「有模板時完全不覆蓋、沒模板時才覆蓋」的精細區分（那套區分邏輯不是問題所在，徒增複雜度）：`.stamp-wrap svg,svg.car-stamp{width:91px;height:91px;}`，**不分是否指定圖章模板、一律套用，也不需要 `!important`**（SVG 的 `width`/`height` 是「表現屬性」，特異度全站最低，任何一條有選到的 CSS 規則都會蓋過去，不需要 `!important`）。
> - 91px 換算回外徑約 2.41cm，跟使用者實測的 2.5cm 有些微落差，但既然 `training_record.php` 用同一個數字印出來使用者驗收通過，代表這個誤差在實務上可接受；**除非有人明確要求更精確，不必為了追求理論上的完美又去改這個數字，改了搞不好又要重踩一次上面那三輪失敗的坑**。真的要精算時公式仍是 `px = 實際外徑公分數 × 96 ÷ 2.54`。
> - 順帶處理：負責單位/人欄的部門與人員之間分隔符從頓號改成「 / 」（例：「資材部 / 吳佳靜」），部門/人員各自內部仍用頓號連接多筆。
>
> 2026-08-13（二次）補充：新增**第9條「抓圖章模板的 API 動作權限不要卡管理員專用」**。起因：使用者在另一個模組 `hr_position_forms.php`（人資職務表單）也回報圖章太小，追出跟 `review_form.php` 同一批問題外，還多一個更隱蔽的根因——`fetchTplForPrint()` 與 `HrForm_API.php` 的 `template_get` 都寫死只有管理員能拿到範本設定，導致非管理員印表單時**即使管理員已經設定好圖章模板，也永遠拿不到、一律退回系統預設章**，畫面上完全看不出是這個原因。已修正（`template_get` 改用 `canPrint`，讀取放寬、寫入仍卡管理員）。同批：`review_form_lib.php` 的 `rvf_notify_item_owners()` 通知標題/內文原本沒帶模板名稱（跟同檔案其他通知不一致），使用者反映「看不出是什麼東西」，已修正成一律帶模板名稱。
> 2026-08-05（三次）補充：新增**第8條「密集逐列表格改用模板填滿列高比例，不沿用固定px」**（使用者明確要求）。起因：教育訓練簽到表/訓練紀錄每人一列印章，套用固定尺寸直接把列高撐爆、每列高度不一致；改成模板可設定 `fillRatio`（預設0.9＝90%）讓章依所在儲存格實際高度等比縮放，另提供 `noScale`（不可縮放）勾選給不能被壓縮的關防章例外使用（**這個 `noScale` 是「密集表格填滿列高」情境下的例外，跟 2026-08-13 整頁縮放那個問題是兩回事，不要混為一談**——密集表格的 `fillRatio` 縮放是 `eg_stamp_tpl.js` 自己算的 inline style，不是 `document.body.style.zoom`）。
> 2026-08-03 制定，使用者明確要求：**簽章欄要是圖章簽章，不是印姓名文字、也不是留一條底線給人手簽。**
> 相關：`ai-rules/16-列印文件標準.md`（大標題／頁碼／文件編號）、`ai-rules/17-審核通知標準.md`（誰簽、怎麼決行）、記憶 `stamp_module`（圖章管理模組）。

## 鐵則

1. **凡是表單上的簽章欄（核准／審核／人事／主管／管理代表／講師…），一律用圖章呈現**，畫面與列印版都是。
   ❌ 只印「王小明」文字　❌ 只畫一條 `______` 底線　❌ 自己畫方框寫名字。
2. **唯一實作點：共用檔 `resource/js/eg_stamp.js`**，禁止各頁自刻印章 SVG。
   ```html
   <script src="../../resource/js/eg_stamp.js?v=<?= @filemtime(__DIR__.'/../../resource/js/eg_stamp.js') ?>"></script>
   ```
   ```js
   window.__ownCompany = COMPANY;              // 公司全名（列印大標題同一來源，見 ai-rules/16）
   var html = EGStamp.stamp(name, 'YYYY-MM-DD');        // 一顆章
   var html = EGStamp.stamp(name, date, true);          // 代理人代簽 → 右下角自動加「代」
   var html = EGStamp.stamp(name, date, false, tplSchema, dept, position);  // 套模板時可選帶部門/職稱(模板內{部門}/{職稱} token才會顯示；掃描章/預設回墨印SVG無此欄位)
   EGStamp.row(stampHtml, leftHtml);                    // 「簽章：」排版列
   ```
3. **有上傳掃描實體章的人自動換成實體章**：`eg_stamp.js` 載入時會向 `store_Stamp_API.php?action=asset_map` 取「姓名→掃描章」對照，
   有章者用去背 PNG 底圖＋**白遮罩蓋掉掃描件上的舊日期**再壓上動態日期；沒上傳的人用共用回墨印 SVG。
   對照表是非同步載入，**已畫出來的章會自動升級替換，消費端不需要改任何程式**。
4. **一定要帶日期**：章面中央的日期帶就是簽章日期。日期來源優先序（沒有簽核紀錄時的表單也要有日期，不可留空）：
   ①該筆簽核紀錄的 `decided_at` → ②模組設定的簽章日期欄位 → ③該份文件的最後異動日 → ④今天。
   **若模組允許「免送審」，就必須另外提供簽章日期設定欄位**（例：教育訓練「計劃表簽章日期」）。
5. **沒有指定簽章人時不要硬蓋章**：該欄留白給紙本蓋章，並在按列印時提醒去
   `views/admin/org_role_setting.php`（組織角色綁定設定）指定；簽章人一律取自那裡，**禁止各頁寫死人名**。
6. **圖章列印尺寸（2026-08-13 三次修正定案，直接抄下面這段，不要自己重新推導）**：
   ```css
   .stamp-wrap svg,svg.car-stamp{width:91px;height:91px;-webkit-print-color-adjust:exact;print-color-adjust:exact;}
   ```
   **不分是否指定圖章模板，一律套用同一條規則；不需要 `!important`**（SVG 的 `width`/`height` 屬性特異度低，一般 CSS 類別選擇器就蓋得過去）。`width`／`height` 一律等值（正方形，來源 `viewBox="0 0 100 100"`），不可只調一邊。
   真的需要精確換算時公式是 `px = 實際外徑公分數 × 96 ÷ 2.54`（96px＝1英吋＝2.54公分），但**除非使用者明確要求更精確的數字，直接套用上面的 91px 即可**，不要自己另外重算一個值——那條路線 2026-08-13 已經來回試了三輪都不如預期（見本檔最上方補充的完整教訓）。
   **畫面上（非列印）的顯示尺寸不受此鐵則限制**，維持各頁原樣（多半是 `eg_stamp.js` 預設的 76px）即可，不必為了改列印尺寸連帶動到螢幕顯示；若某頁的畫面就是「列印預覽」本身（同一份 DOM 只用 `@media print` 切換），則只在 `@media print{}` 區塊內加尺寸覆蓋，不要動到區塊外的一般樣式。
7. **簽章格高度要留給章**（≥95px，含章體91px加上下留白），不要沿用只放一行字的高度，否則章會被壓扁或撐破表格。
8. **絕對不要把「圖章列印」跟「整頁自動縮放塞進一頁」（`document.body.style.zoom`）混在一起用**（2026-08-13 鐵則，血淚教訓，見本檔最上方完整補充）。這兩者天生互斥：圖章需要維持固定真實尺寸，而整頁縮放是為了讓內容剛好塞進一張紙，只要圖章不跟著縮，就會撐大內容高度、讓縮放比例的估算失準，不管用反向補償 `zoom` 還是 `position:fixed` 逃脫縮放的圖層技巧，都無法徹底解決（`review_form.php` 這兩招都試過，仍有殘留縮小）。
   **列印分頁一律比照 `print_pagination` 鐵則、`training_record.php` 既有作法：分頁 100% 交給瀏覽器引擎原生處理，內容超過一頁就自然分頁，不要用 JS 量高度硬壓成一頁**。表格常常剛好超過一頁時，正確的因應方式是把字級/欄位留白**設計得收斂一點**（見 `review_form.php` 的 `rfCss()` 最終定案：12px 字級、6px 7px padding），不是靠列印當下硬縮。
   頁碼「超過一頁才顯示」的邏輯（`ai-rules/16` 第二節）跟這條無關，可以正常保留——那只是量高度決定要不要插入 `@page{@bottom-left{counter(page)...}}` 的 CSS，完全不影響分頁本身、也不碰圖章。
9. **抓「圖章模板」設定的 API 動作，權限不要卡管理員專用**（2026-08-13 新增，`hr_position_forms.php` 案例）。背景：`views/ADM/hr_position_forms.php` 印表單時會呼叫 `template_get` 拿這份表單綁定的圖章模板，前端 `fetchTplForPrint()` 原本寫 `if (!META.perms.canAdmin) { cb(null); return; }`，後端 `HrForm_API.php` 的 `template_get` 動作也卡 `if (!$perms['canAdmin'])`——**等於只有管理員印表單才拿得到模板，其他人一律 `schema=null` 退回系統預設章，即使管理員已經幫這份表單設定好模板也沒用**。這是「圖章太小」的根因之一，比純 CSS 覆蓋問題更隱蔽（畫面上完全看不出來，要追兩層 code 才看得到）。
    正確做法：**同一個 API 動作若同時服務「管理員編輯範本」與「一般使用者列印要拿圖章模板」兩種情境，讀取（`_get`）應該對兩種情境都放行，只有寫入（`_save`）才卡管理員**——`template_get` 這種動作改用「這個模組本來就有的『可列印』權限」（例：`canPrint`）而不是 `canAdmin`；`template_save`/`template_delete` 這類寫入動作維持只有管理員能動。改完前端呼叫端的權限判斷也要同步放寬，不要只改一邊（後端放寬了、前端 `if(!canAdmin)` 沒改，一樣拿不到）。範例：`HrForm_API.php` 的 `template_get`（改用 `canPrint||canAdmin`）＋`hr_position_forms.php` 的 `fetchTplForPrint()`（同步放寬）。
    **`review_form.php` 從一開始就沒有這個坑**：`ReviewForm_API.php` 的 `template_get` 本來就沒有額外卡權限（只受 API 最上層的 `canView` 把關），新模組抄範本時若沒有對照到這個細節、自己另外加了 `canAdmin` 限制，就會複製出這個坑——**寫新模組時「印表單要拿的設定資料」一律比照 `canView`/`canPrint` 這種寬鬆等級，不要照抄「編輯這個設定」用的 `canAdmin` 判斷**。
10. **密集逐列表格（簽到表/名單每人一格印章）不要沿用第6條的固定尺寸**——那是給「有充足空間的簽核欄」用的，硬套在每人一列的名單表格會把列高撐爆、跟其他列不一致（2026-08-05 教育訓練簽到表踩到的坑）。
    正確做法：到「圖章管理 → 線上圖章設計」該模板設定**填滿列高比例**（`fillRatio`，預設 0.9＝90%）。`eg_stamp.js` 的 `tplStamp()` 會自動用 inline `style="height:{fillRatio*100}%"` 讓章依所在儲存格（`<td>`）的實際高度等比縮放——**前提是該儲存格本身要有明確的 CSS `height`**，否則百分比高度不生效、退回原尺寸。
    若某模板依規定不可被壓縮（例：法規要求固定尺寸的關防），勾選模板的**「不可縮放」**（`noScale`，這是模板自己 `fillRatio` 機制內的選項，跟第8條講的「整頁縮放」是兩個不同的縮放來源，不要混淆），列印時一律用模板設計的實際大小（`大小(px)`×`高/寬比`），即使超出格子高度也不縮小，允許蓋出格子外。
    掃描實體章／沒有指定模板時退回的泛用 SVG 章沒有 `fillRatio` 可設，這種情況由消費頁面在該密集表格自己的 CSS 提供一個相容的 `height:百分比` 退回值（範例見 `training_record.php` 簽到表：`table.sf .stamp-wrap{height:90%;display:inline-flex;align-items:center;}table.sf .stamp-wrap svg{height:100%;width:auto;}`），維持跟模板同樣「填滿列高」的觀感，**不要用固定 px 猜尺寸**（猜大了撐爆列高、猜小了字看不清，且換一張表格列高不同又要重猜一次）。

## 檢查清單

- [ ] 有載 `eg_stamp.js` 並設定 `window.__ownCompany`？
- [ ] 簽章欄用 `EGStamp.stamp()`，不是文字或底線？
- [ ] 章面有日期？免送審的表單有提供「簽章日期」設定？
- [ ] 簽章人取自組織角色綁定，沒設定時留白＋提醒，而不是空白印出去？
- [ ] 列印版章的大小、紅色都正常（`print-color-adjust:exact`）？
- [ ] 圖章尺寸 CSS 是不是直接抄第6條的 `.stamp-wrap svg,svg.car-stamp{width:91px;height:91px;}`，沒有自己另外發明數字或加不必要的 `!important`／schema 區分邏輯？
- [ ] **這個列印流程有沒有 `document.body.style.zoom` 之類的整頁自動縮放塞一頁邏輯？有的話一律拿掉，改交給瀏覽器引擎原生分頁**（第8條鐵則，不要嘗試用反向補償或 fixed 圖層逃脫縮放，那條路已知走不通）。
- [ ] 是密集逐列表格（每人一格印章）嗎？是的話該儲存格有沒有明確 `height`、模板 `fillRatio`/`noScale` 有沒有設對（第10條，這裡的 `noScale` 跟第8條的整頁縮放無關）？
- [ ] 抓圖章模板的 API 動作（`template_get` 之類）權限有沒有卡成管理員專用？前後端都要檢查（第9條）。

## 既有可抄的範例

- `views/ADM/training_record.php`：**圖章尺寸與「不做整頁縮放」的原始參考範例**——`egStampHtml()` / `signRowHtml()`（核准・審核・人事三欄圖章＋日期優先序）；`egPrintWindow()` 完全沒有 `zoom`/`scale` 邏輯，分頁交給瀏覽器引擎原生處理；`printSignSheet()`/`printRecord()` 的 `table.sf` 是「密集逐列表格改用填滿列高比例」的範例。
- `views/ADM/review_form.php`：`stampOrName()`/`rfCss()`/`egPrintWindow()`——2026-08-13 繞了四輪才改成跟 `training_record.php` 一致的簡單寫法，過程教訓見本檔最上方補充；`ReviewForm_API.php` 的 `template_get` 從一開始就沒有卡管理員，是第9條「讀取權限不要照抄編輯用的canAdmin」的正確示範。
- `views/ADM/hr_position_forms.php`：`stampOrName()`/`hfPrintCss()`/`fetchTplForPrint()`——沒有整頁縮放邏輯，圖章尺寸單純；同時是第9條「權限卡太緊讓模板設定形同虛設」的實際案例與修正範例（`HrForm_API.php` 的 `template_get` 改用 `canPrint`）。
- `views/QA/correction_order.php`（章的原始出處）、`views/ADM/leave_request.php`、`views/ADM/as_form_fill.php`
- `views/ADM/stamp_management.php`：線上圖章設計模板的 `填滿列高比例`／`不可縮放`／`大小(px)↔公分外徑換算` 設定 UI（`tplSchemaFromUI()`/`openTplModal()`/`tplSizeCmSync()`）——公分換算輸入框可用，但**存進 schema 的仍是 px**，不影響第6條「直接用91px即可」的建議。
