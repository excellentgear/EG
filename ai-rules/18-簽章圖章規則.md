# 18. 簽章一律用「圖章」（全站表單／列印文件通用）

> 2026-08-13（二次）補充：新增**第10條「抓圖章模板的 API 動作權限不要卡管理員專用」**。起因：使用者在另一個模組 `hr_position_forms.php`（人資職務表單）也回報圖章太小，追出跟 `review_form.php` 同一批問題外，還多一個更隱蔽的根因——`fetchTplForPrint()` 與 `HrForm_API.php` 的 `template_get` 都寫死只有管理員能拿到範本設定，導致非管理員印表單時**即使管理員已經設定好圖章模板，也永遠拿不到、一律退回系統預設章**，畫面上完全看不出是這個原因。已修正（`template_get` 改用 `canPrint`，讀取放寬、寫入仍卡管理員）並比照 `review_form.php` 套用第6條的尺寸換算＋尊重模板大小做法（`hr_position_forms.php` 沒有整頁縮放邏輯，不需要第8條的noScale反向補償）。同批：`review_form_lib.php` 的 `rvf_notify_item_owners()` 通知標題/內文原本沒帶模板名稱（跟同檔案其他通知不一致），使用者反映「看不出是什麼東西」，已修正成一律帶模板名稱；`review_form.php` 列印字級/欄高使用者實測後又再加大一輪（13.5px→15.5px）。
> 2026-08-13 補充（重要，推翻部分舊規則，見第6/8條）：使用者實測回報 `review_form.php` 列印出來的圖章「還是感覺很小」，追出兩個根因並修正：
> ①**91px 這個數字本身沒有依據**——2026-08-05 制定時只是「以 `quotation_list_NEW.php` 現況為準」，沒有真的拿實體圖章去量過。使用者這次提供實測值：圖章實際外徑 **2.5 公分**，換算 `2.5 × 96 ÷ 2.54 ≈ 94.5px`（96px＝1英吋＝2.54公分，跟 `ai-rules/16` 算分頁高度用的同一套換算公式）。**91px 換算回外徑只有 2.41cm，比實際小了一截**，這就是「感覺很小」的其中一個原因。
> ②**更關鍵的根因：舊規則用 `!important` 把「所有」圖章都蓋成同一個固定值，蓋掉了「圖章管理→線上圖章設計」（`stamp_management.php`）裡模板自己設定的「大小(px)」**——使用者明明已經在模板裡設定了想要的大小，卻被列印 CSS 強制蓋掉，等於那個設定完全沒有作用。這是本次真正修正的地方，做法與原因寫進第6/8條，供其他頁面比照同一套邏輯修正（目前**只有 `review_form.php` 改過**，`training_record.php`／`vendor_audit.php`／`correction_order.php`／`as_document_management.php`／`inspection_entry_v2.php`／`as_form_fill.php` 仍是舊的固定 91px，尚未回頭改，之後有人動這些頁面時應比照同一套方式修正）。
> ③`stamp_management.php` 的「大小(px)」欄位旁新增「公分外徑」輸入框，兩者雙向即時換算（同一套 96px=2.54cm 公式），設計模板時可以直接輸入實體圖章量出來的外徑公分數，不用自己心算 px。schema 儲存格式不變，仍然只存 px，向下相容既有模板。
>
> 2026-08-05（三次）補充：新增**第8條「密集逐列表格改用模板填滿列高比例，不沿用固定91px」**（使用者明確要求）。起因：教育訓練簽到表/訓練紀錄每人一列印章，套用第6條固定91px直接把列高撐爆、每列高度不一致；改成模板可設定 `fillRatio`（預設0.9＝90%）讓章依所在儲存格實際高度等比縮放，另提供 `noScale`（不可縮放）勾選給不能被壓縮的關防章例外使用。第6條91px仍是「有充足空間簽核欄」（如核准/審核/人事三欄式簽核區）的預設值，兩者並存、依欄位性質選用。

> 2026-08-03 制定，使用者明確要求：**簽章欄要是圖章簽章，不是印姓名文字、也不是留一條底線給人手簽。**

## 鐵則

1. **凡是表單上的簽章欄（核准／審核／人事／主管／管理代表／講師…），一律用圖章呈現**，畫面與列印版都是。
   ❌ 只印「王小明」文字　❌ 只畫一條 `______` 底線　❌ 自己畫方框寫名字。
2. **唯一實作點：共用檔 `resource/js/eg_stamp.js`**，禁止各頁自刻印章 SVG。
   ```html
   <script src="../../resource/js/eg_stamp.js?v=<?= @filemtime(__DIR__.'/../../resource/js/eg_stamp.js') ?>"></script>
   ```
   ```js
   window.__ownCompany = COMPANY;              // 公司全名（列印大標題同一來源，見 ai-rules/16）
   var html = EGStamp.stamp(name, 'YYYY-MM-DD');        // 一顆章
   var html = EGStamp.stamp(name, date, true);          // 代理人代簽 → 右下角自動加「代」
   var html = EGStamp.stamp(name, date, false, tplSchema, dept, position);  // 套模板時可選帶部門/職稱(模板內{部門}/{職稱} token才會顯示；掃描章/預設回墨印SVG無此欄位)
   EGStamp.row(stampHtml, leftHtml);                    // 「簽章：」排版列
   ```
3. **有上傳掃描實體章的人自動換成實體章**：`eg_stamp.js` 載入時會向 `store_Stamp_API.php?action=asset_map` 取「姓名→掃描章」對照，
   有章者用去背 PNG 底圖＋**白遮罩蓋掉掃描件上的舊日期**再壓上動態日期；沒上傳的人用共用回墨印 SVG。
   對照表是非同步載入，**已畫出來的章會自動升級替換，消費端不需要改任何程式**。
4. **一定要帶日期**：章面中央的日期帶就是簽章日期。日期來源優先序（沒有簽核紀錄時的表單也要有日期，不可留空）：
   ①該筆簽核紀錄的 `decided_at` → ②模組設定的簽章日期欄位 → ③該份文件的最後異動日 → ④今天。
   **若模組允許「免送審」，就必須另外提供簽章日期設定欄位**（例：教育訓練「計劃表簽章日期」）。
5. **沒有指定簽章人時不要硬蓋章**：該欄留白給紙本蓋章，並在按列印時提醒去
   `views/admin/org_role_setting.php`（組織角色綁定設定）指定；簽章人一律取自那裡，**禁止各頁寫死人名**。
6. **開新視窗列印時**：章的 HTML 在父視窗用 `EGStamp.stamp()` 產生好再塞進列印視窗（SVG 是自包含字串、掃描章的圖走絕對路徑 `/EGsystem/src/store/...`，新視窗一樣讀得到）。
   列印 CSS 記得給尺寸與 `-webkit-print-color-adjust:exact`（章是紅色，否則印出來會掉色）。

   **尺寸換算公式（2026-08-13 制定，取代舊的「全站統一91px」）**：`px = 實際外徑公分數 × 96 ÷ 2.54`（96px＝1英吋＝2.54公分，跟 `ai-rules/16` 算列印分頁高度的換算公式同一套，全站不要各自發明別的換算方式）。**舊的91px是2026-08-05沒有真的拿實體圖章去量、只是抄 `quotation_list_NEW.php` 現況訂下來的，換算回外徑只有2.41cm，並不準**；之後任何頁面要調整圖章列印尺寸，一律先問使用者「這顆章實際外徑幾公分」，用這條公式現算，不要沿用舊的91px或憑感覺猜一個數字。

   **不要用固定尺寸蓋掉「有指定圖章模板」的章**（2026-08-13 修正，起因：`review_form.php` 舊寫法無條件 `svg.car-stamp{width:91px!important;...}` 蓋住所有章，導致使用者在「圖章管理→線上圖章設計」（`stamp_management.php`）幫這份文件設定好的模板尺寸完全沒有作用，這是「感覺很小」的主因，比91px本身算錯還關鍵）。正確做法是**區分兩種情況**：
   - **有指定圖章模板**（`EGStamp.stamp()` 第4參數 `tplSchema` 有值）：模板自己的「大小(px)」（`tplSchemaFromUI()` 存進 schema 的 `size` 欄位）已經是設計時要的實際尺寸，**完全尊重、不要用 CSS 覆蓋**；管理員要調整就直接去模板設計頁改，不需要也不應該讓頁面的列印 CSS 插手。
   - **沒有指定模板**（退回 `eg_stamp.js` 內建的預設回墨印/掃描章，`width="76" height="76"` 只是 SVG 屬性，不代表真實尺寸）：**才**需要在列印 CSS 用**一個獨立的 class**（不要直接選 `svg.car-stamp`，那樣會連模板章一起選到）覆蓋成上面公式換算出來的實際尺寸，例如：
     ```css
     /* 只套用在「沒有指定模板」時包的外層 class，不要用 svg.car-stamp 這種會連模板章一起選中的選擇器 */
     .rf-stamp-defsize svg { width:94.5px !important; height:94.5px !important; -webkit-print-color-adjust:exact; print-color-adjust:exact; }
     ```
     JS 端在組印章 HTML 時依「有沒有 schema」決定要不要包這層 class（範例見 `views/ADM/review_form.php` 的 `stampOrName()`）：
     ```js
     function stampOrName(name, date, isDeputy, schema){
       var html = EGStamp.stamp(name, date, !!isDeputy, schema);
       if (!schema) html = '<span class="rf-stamp-defsize">'+html+'</span>';   // 沒模板才蓋固定尺寸
       else if (schema.noScale) html = '<span class="rf-stamp-noshrink">'+html+'</span>';  // 見下方noScale+整頁縮放說明
       return html;
     }
     ```
   `width`／`height` 一律等值（正方形，來源 `viewBox="0 0 100 100"`），不可只調一邊。
   **畫面上（非列印）的顯示尺寸不受此鐵則限制**，維持各頁原樣（多半是 `eg_stamp.js` 預設的 76px）即可，不必為了改列印尺寸連帶動到螢幕顯示；若某頁的畫面就是「列印預覽」本身（例如同一份 DOM 只用 `@media print` 切換），則只在 `@media print{}` 區塊內加尺寸覆蓋，不要動到區塊外的一般樣式。
7. **簽章格高度要留給章**（≥95px，含章體約94.5px加上下留白，依實際換算出的 px 值調整，不要照抄某個頁面用剩的舊數字），不要沿用只放一行字的高度，否則章會被壓扁或撐破表格。
8. **「不可縮放」（`noScale`）遇到整頁縮放塞一頁的列印引擎時，要反向補償才會真的不縮小**（2026-08-13 新增，`review_form.php` 案例）。背景：不少頁面的列印用 `document.body.style.zoom = pageH/scrollHeight` 之類的手法把整個頁面等比縮小塞進一張紙（`egPrintWindow()` 常見寫法），這個縮放是套在 `<body>` 上、會連帶影響底下所有子元素——包含勾了「不可縮放」原本應該堅持原尺寸的圖章。
   做法：CSS 的 `zoom` 屬性是**逐層相乘**的（子元素設 `zoom` 是疊加在祖先已經套用的縮放之上，不是取代），所以只要在 body 縮放定案後，對那些標記為「不可縮放」的圖章元素另外設 `style.zoom = 1/bodyZoomRatio`，兩層縮放相乘後淨效果就會抵銷回原始設計大小：
   ```js
   var zr = 1;
   if (document.body.scrollHeight > pageH) { zr = Math.max(0.5, pageH / document.body.scrollHeight); document.body.style.zoom = zr; }
   if (zr < 1) {
     document.querySelectorAll('.rf-stamp-noshrink').forEach(function(el){ el.style.zoom = (1/zr); });   // 反向補償，抵銷body縮放
   }
   ```
   哪些圖章要標記 `.rf-stamp-noshrink`：由模板的 `schema.noScale` 決定（見上一條的 `stampOrName()` 範例），不是所有圖章都要補償——沒勾「不可縮放」的章本來就允許跟著整頁一起縮小，不需要特別處理。
9. **密集逐列表格（簽到表/名單每人一格印章）不要沿用第6條的固定尺寸**——那是給「有充足空間的簽核欄」用的，硬套在每人一列的名單表格會把列高撐爆、跟其他列不一致（2026-08-05 教育訓練簽到表踩到的坑）。
   正確做法：到「圖章管理 → 線上圖章設計」該模板設定**填滿列高比例**（`fillRatio`，預設 0.9＝90%）。`eg_stamp.js` 的 `tplStamp()` 會自動用 inline `style="height:{fillRatio*100}%"` 讓章依所在儲存格（`<td>`）的實際高度等比縮放——**前提是該儲存格本身要有明確的 CSS `height`**，否則百分比高度不生效、退回原尺寸。
   若某模板依規定不可被壓縮（例：法規要求固定尺寸的關防），勾選模板的**「不可縮放」**（`noScale`），列印時一律用模板設計的實際大小（`大小(px)`×`高/寬比`），即使超出格子高度也不縮小，允許蓋出格子外。
   掃描實體章／沒有指定模板時退回的泛用 SVG 章沒有 `fillRatio` 可設，這種情況由消費頁面在該密集表格自己的 CSS 提供一個相容的 `height:百分比` 退回值（範例見 `training_record.php` 簽到表：`table.sf .stamp-wrap{height:90%;display:inline-flex;align-items:center;}table.sf .stamp-wrap svg{height:100%;width:auto;}`），維持跟模板同樣「填滿列高」的觀感，**不要用固定 px 猜尺寸**（猜大了撐爆列高、猜小了字看不清，且換一張表格列高不同又要重猜一次）。
10. **抓「圖章模板」設定的 API 動作，權限不要卡管理員專用**（2026-08-13 新增，`hr_position_forms.php` 案例，跟第6條同一批問題一起發現）。背景：`views/ADM/hr_position_forms.php` 印表單時會呼叫 `template_get` 拿這份表單綁定的圖章模板，前端 `fetchTplForPrint()` 原本寫 `if (!META.perms.canAdmin) { cb(null); return; }`，後端 `HrForm_API.php` 的 `template_get` 動作也卡 `if (!$perms['canAdmin'])`——**等於只有管理員印表單才拿得到模板，其他人一律 `schema=null` 退回系統預設章，即使管理員已經幫這份表單設定好模板也沒用**。這是「圖章太小」的根因之一，比第6條的 CSS 覆蓋問題更隱蔽（畫面上完全看不出來，要追兩層 code 才看得到）。
    正確做法：**同一個 API 動作若同時服務「管理員編輯範本」與「一般使用者列印要拿圖章模板」兩種情境，讀取（`_get`）應該對兩種情境都放行，只有寫入（`_save`）才卡管理員**——`template_get` 這種動作改用「這個模組本來就有的『可列印』權限」（例：`canPrint`）而不是 `canAdmin`；`template_save`/`template_delete` 這類寫入動作維持只有管理員能動。改完前端呼叫端的權限判斷也要同步放寬，不要只改一邊（後端放寬了、前端 `if(!canAdmin)` 沒改，一樣拿不到）。範例：`HrForm_API.php` 的 `template_get`（改用 `canPrint||canAdmin`）＋`hr_position_forms.php` 的 `fetchTplForPrint()`（同步放寬）。
    **`review_form.php` 從一開始就沒有這個坑**：`ReviewForm_API.php` 的 `template_get` 本來就沒有額外卡權限（只受 API 最上層的 `canView` 把關），新模組抄範本時若沒有對照到這個細節、自己另外加了 `canAdmin` 限制，就會複製出這個坑——**寫新模組時「印表單要拿的設定資料」一律比照 `canView`/`canPrint` 這種寬鬆等級，不要照抄「編輯這個設定」用的 `canAdmin` 判斷**。

## 檢查清單

- [ ] 有載 `eg_stamp.js` 並設定 `window.__ownCompany`？
- [ ] 簽章欄用 `EGStamp.stamp()`，不是文字或底線？
- [ ] 章面有日期？免送審的表單有提供「簽章日期」設定？
- [ ] 簽章人取自組織角色綁定，沒設定時留白＋提醒，而不是空白印出去？
- [ ] 列印版章的大小、紅色都正常（`print-color-adjust:exact`）？
- [ ] 是密集逐列表格（每人一格印章）嗎？是的話該儲存格有沒有明確 `height`、模板 `fillRatio`/`noScale` 有沒有設對，不是照抄某個固定 px 數字？
- [ ] **列印尺寸有沒有問使用者「這顆章實際外徑幾公分」，用 `px = 公分×96÷2.54` 現算，不是沿用其他頁面抄來的舊數字（91px 已知不準，見第6條說明）？**
- [ ] **列印 CSS 有沒有不分青紅皂白用 `svg.car-stamp`／`.stamp-wrap svg` 這種會連「有指定圖章模板」的章一起選中的選擇器蓋尺寸？應該只在「沒有指定模板」時才蓋固定尺寸，有模板時尊重模板自己的「大小(px)」。**
- [ ] 這個列印流程有沒有整頁自動縮放塞一頁（`document.body.style.zoom` 之類）？有的話，勾了「不可縮放」的章有沒有做反向補償（`el.style.zoom = 1/bodyZoomRatio`），不然照樣會被拖著縮小。
- [ ] **抓圖章模板的 API 動作（`template_get` 之類）權限有沒有卡成管理員專用？前後端都要檢查**——只有「編輯/儲存範本」才該卡管理員，「印表單要拿模板設定」這種讀取動作全體使用者都要拿得到，不然畫面上完全看不出來，非管理員印出來的章會悄悄退回系統預設樣式。
