# 25-量具顯示規範（檢驗設備一覽表 qc_tool 在其他頁面怎麼顯示、怎麼挑）

> 訂定：2026-09-23，使用者明確要求
> 原話：「`views/QC/tool_calibration.php` 內要可以依照類別設定顯示在其他選單上是哪些欄位，
> 或是哪些加哪些欄位一起顯示，像是跨珠分厘卡適合 量具編號＋規格，
> 類別全部當訂在檢測機的就可以直接顯示機台名稱。
> **要依照量測儀器頁面內綁定在同一頁的設定，同一種其他頁面的顯示方式，
> 這規定應該要寫入 MD，避免每個頁面又要重新說一次。**」

**唯一實作：`src/common/qc_tool_display_lib.php`。設定入口只有一個：量測儀器校驗管理 →「類別設定」。**
任何頁面要「列出量具給人挑」或「顯示某一支量具」，一律呼叫本庫，**禁止各頁自己拼字串、自己寫 SQL 條件**。

---

## 一、state 的語意（已經害過一次，先講這個）

**`qc_tool.state`：`1` ＝停用，`0` 或 `NULL` ＝在用。**
（建欄註解就寫著「0/NULL=正常，比照 `machine_list.state` 語意」，見 `tool_calib_lib.php`。）

`sopsip_lib.php` 原本寫成 `(state IS NULL OR state<>0)` ＝**把在用的整批當成停用**，
結果在用的 QC-001／QC-002 在 SIP 的「挑檢具編號」裡一支都看不到、
已經停用的 QC-003 反而一直列出來，**而且完全不報錯**——
畫面上只是「少了兩支量具」，看起來像資料沒建好不像 bug。
更難查的是：使用者在量測儀器校驗頁編輯過的量具會被寫成 `state=0`（在用），
於是「**改過名字的量具會突然從別的頁面消失**」（實測 K-555-P 就是這樣不見的）。

往後一律用：

| 要做的事 | 呼叫 |
|---|---|
| SQL 裡判在不在用 | `qc_tool_active_cond('t')` → `COALESCE(t.state,0)<>1` |
| PHP 裡判一列在不在用 | `qc_tool_is_active($row)` |
| 判「**業務日期那一天**在不在用」 | `qc_tool_active_asof($row, $date)` |

`machine_list.state` 是同一套語意（`'1'` 才是停用），機台端請用 `ss_machine_active_cond()`。

## 二、停用的量具／機台不可以直接不見

**補歷史資料時一定要挑得到**（使用者 2026-09-23：「停用的機台一樣要可以補資料，
可以看到我的表單日期是 2022，那時候根本還沒停用」）。

規則：

1. 挑選清單一律把**表單日期（業務日期）**傳進去（`asof`）。
2. 停用日期**晚於**表單日期的：照常可挑（`usable=1`），但要標示「已停用 YYYY.MM.DD」。
3. 其餘停用的：**仍然列出來但不可點**（反灰＋說明），**不可以安靜地消失**——
   消失的話使用者只會覺得「以前明明有、現在不見了」。
4. 停用日期沒填的（實測機台 8 台停用的有 1 台沒填）：一律只當「現在不可用」。
5. 清單排序：**在用的在前、停用的一律排到最後**（`tool_calibration.php` 的主清單也一樣，
   並整列反灰）。

## 三、顯示哪些欄位：逐類別設定，不要各頁自己決定

量具編號本身看不出是什麼：`QC-001` 現場叫它「TTi 齒輪量測機」、
`K-555-P` 現場講的是「100-125mm」。所以**每個量具類別（`qc_tool_list`）各自設定
「被別的頁面挑選時要印哪幾欄」**：

* 設定入口：量測儀器校驗管理 →「類別設定」→ 最右邊的「其他頁面顯示」欄（可即時預覽）。
* 存放：`system_settings.qc_tool_display_cfg`（一列 JSON，`{類別id: {fields:[], sep:''}}`）。
* 可選欄位的**唯一登記處**＝`qc_tool_disp_fields()`；新增欄位只改那一支，所有頁面自動有。
* 沒設定過的類別用 `qc_tool_disp_default()`＝**量具編號＋機台名稱＋規格**。
* **重複或互相包含的欄位會自動合併**：`K-555-P` ⊂ `K-555-P (100-125mm)` ⊃ `100-125mm`
  只會印出最長的那一個，不會變成「K-555-P K-555-P (100-125mm) 100-125mm」。

取得顯示文字：`qc_tool_disp_label($db, $row)`。**不要自己 `$row['Tool_No'].' '.$row['spec_desc']`。**

## 四、挑量具的清單一律走同一支

```php
require_once __DIR__ . '/qc_tool_display_lib.php';

$rows = qc_tool_pick_rows($db, [
    'type_id'  => 10,            // 只要某個類別（選填）
    'kw'       => '齒輪',        // 關鍵字（編號／類別／機台名稱／規格／製造商都比得到）
    'asof'     => '2022-03-10',  // 業務日期；有給時停用的也列出來並算出 usable
    'with_off' => 1,             // 1＝連停用的也列（有 asof 時自動為 1）
]);
// 每一列：tool_id / tool_no / label / type_id / type_name / spec_desc / machine /
//         manufacturer / disabled / disabled_date / usable
```

單支：`qc_tool_pick_one($db, $toolId)`（回同樣的欄位，找不到回 `null`）。

## 五、存的是 Tool_id，不是編號文字（鐵律4）

**任何模組要記「用了哪一支量具」，一律存 `qc_tool.Tool_id`。**
存編號文字的話，量具在檢驗設備一覽表改個名字就對不回主檔了，
而且**不會報錯**——畫面上只是那個選項默默消失（實測 K-555-P 改名後就是這樣）。

* 編號與顯示文字一律**讀取當下即時回查**（`qc_tool_pick_one()`）。
* 要留一個 `tool_no` 欄位當顯示快取可以，但它**只是快取**：
  每次寫入時由主檔重新填，讀取時也以主檔為準；主檔那一支被刪掉才退回顯示舊文字並標明。
* 參考實作：`ss_item.tool_id` / `ss_item_tpl.tool_id`（SOP／SIP 的檢驗項目）。

## 六、挑選 UI 的規則

* **不給手打**：檢具欄位一律 `readonly`＋「挑檢具」按鈕（使用者 2026-09-23：
  「檢具編號不可手動輸入，避免輸入錯誤，請限制使用點選」）。
* **沒挑就是 `N/A`**：留空白在紙本上看起來像漏填；前端顯示 N/A，
  後端 `tool_id<=0` 時也一律寫 `N/A`（前端擋一次、後端同規則再擋一次＝鐵律8）。
* 兩段式：先點**類別**、再點**編號**（與線上檢驗「選擇本單使用的量具」同一套手勢）。

## 八、排序：類別在選單上的順序＝ `qc_tool_list.sort_order`，可拖曳設定

> 訂定：2026-09-24，使用者明確要求「要提供當量具為選單時的排序順序可以讓管理員拖移設定」

**唯一排序依據＝ `qc_tool_list.sort_order`。** 設定入口＝量測儀器校驗管理 →「類別設定」，
每一列最左邊「☰」按住上下拖曳（`resource/js/Sortable.min.js`，全站既有共用檔，
把手**限定在最左邊那一格**——這張表其他欄有輸入框，整列可拖會讓在那欄選字變成拖列，
SOP/SIP 已踩過同一個坑），按「儲存」時後端 `save_categories` 直接拿送出陣列的位置當
`sort_order` 寫回（**不要另外收一個 `sort_order` 欄位**——送出順序本身就是使用者要的順序，
兩邊各算一套只會對不起來）。

這顆設定同時決定：

1. `tool_calibration.php` 上方分頁列（`buildTabs()` 依 `sort_order` 排）。
2. `qc_tool_pick_rows()`（本庫 §4，全站唯一挑量具清單）的排列順序。
3. `views/QC/inspection_entry_v2.php`「選擇本單使用的量具」跳窗①先點類型的按鈕排列
   （`TOOL_CATS_ORDER`，見下方相容表的既有 bug）。

**新增類別／新增分頁只是「不改順序」，不是「不能用」**：新類別預設插在最後（`sort_order`
取現有最大值 +1），管理員要移到別的位置一樣是拖曳＋儲存。

### 已修的既有 bug（挑選跳窗的類型順序曾經沒有依這顆設定）

`inspection_entry_v2.php` 的 `tpRenderCats()`（先點類型的按鈕）原本是拿
`inspection_combined_prototype.php` 的 `get_tool_manage_data` 回傳的 `tools` 陣列，
用「哪個類型的第一支量具先出現」去湊類型順序；而那份 `tools` 查詢原本寫
`ORDER BY t.Tool_No ASC`，跟 `qc_tool_list.sort_order` 完全無關——兩層都繞過了
管理員排好的順序，按鈕順序其實是偶然值，**改了「類別設定」的順序，這個跳窗看起來完全沒反應**。
已雙重修正：SQL 改 `JOIN qc_tool_list ORDER BY l.sort_order, l.QC_Tool_List_id, t.Tool_No`；
JS 另外用 `res.categories`（已經是 `sort_order` 排好的）組出 `TOOL_CATS_ORDER`，
`tpRenderCats()` 直接照它排、不再用「第一次出現」推順序。
