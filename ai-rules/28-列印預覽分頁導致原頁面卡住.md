# 28 — 列印時開出預覽分頁，使用者關掉後原頁面輸入框「沒有游標、點不到」

> 建立：2026-11-19　來源：`views/pm/packing_schedule.php` 的「列印包裝標籤」（使用者回報並確認修好）

## 症狀（一模一樣就先看這篇）
- 按「列印」→ 自動開出預覽分頁（呼叫 `window.print()`）→ **沒有真的列印**，直接把預覽分頁關掉回到原頁面。
- 原頁面再開同一個跳窗，**輸入框沒有游標、點不到、打不了字**。
- `php -l`、`node --check`、看原始碼都找不到問題；用無頭 Chrome 模擬「開新分頁再關掉」也**重現不出來**（無頭模式不會真的跳出列印對話框）。

## 真因
用 `window.open('', '_blank')` 開出來的分頁，與原頁面**同一個瀏覽內容群組、同一個瀏覽器程序**。子分頁的 `window.print()` 會一直等使用者操作列印對話框；
使用者不按列印、直接關掉預覽時，原頁面所在的程序還處在被卡住的狀態，回來之後輸入框就失去游標與點擊。

## 錯誤的修法（都試過、都沒用，別再走）
1. 把跳窗的 Bootstrap `fade` 動畫拿掉、換 `backdrop:false`
2. 開窗前 `.modal('hide')`、清掉殘留的 `.modal-backdrop`
3. 改成自製 `display:block/none` 視窗、`mousedown` 強制 `focus()`
4. 固定延遲 `setTimeout(focus, 300)`

→ 問題不在跳窗本身，在「預覽分頁跟原頁面綁在同一個程序」。

## 正確做法（已驗證有效）
**預覽分頁用 Blob 網址＋`noopener` 開成獨立的瀏覽內容**，不要 `window.open('')` 之後再 `document.write`：

```js
var url = URL.createObjectURL(new Blob([html], { type: 'text/html;charset=utf-8' }));
window.open(url, '_blank', 'noopener');
setTimeout(function () { URL.revokeObjectURL(url); }, 120000);
```

`noopener` 之後拿不到 `window.open` 的回傳值（一律 null），所以：
- **資料要在開預覽之前就備好**：開跳窗時先 `$.post` 預載（例：`LB_DATA`），按列印那一下**同步**開預覽，才不會被瀏覽器的彈出視窗封鎖（非使用者手勢觸發的 `window.open` 會被靜默擋掉）。
- 沒預載到資料才退回「先取資料再開」，並提示使用者允許彈出視窗。
- 預覽 HTML 內自己 `window.onload → setTimeout(print, 250)`，原頁面不再呼叫子視窗的任何方法。

另加一道保險：從預覽回到本頁時，跳窗還開著卻沒有輸入框有焦點，就補回游標：
```js
$(window).on('focus', function () {
    if (!$('#labelModal').is(':visible')) return;
    if (!$(document.activeElement).closest('#labelModal').length) $('#lb-rows .lb-q').first().focus();
});
```

## 驗證方式
- 無頭 Chrome（自己的 `--user-data-dir`、冷門埠、只終止自己的 PID，見 CLAUDE.md 鐵律9）模擬：開跳窗→輸入→列印→關掉子分頁→再開，連做 3 輪，每輪用 `elementFromPoint` 確認輸入框在最上層、`Input.insertText` 確認打得進去。
- 子分頁的 `window.opener === null` 才代表真的獨立。
- **無頭模式測不到真正的列印對話框**，必須請使用者在自己的瀏覽器實際「按列印→不列印直接關掉預覽→再開」確認。

## 其他頁面
全站凡是「`window.open('', '_blank')` ＋ `document.write` ＋ `window.print()`」的列印寫法理論上都有同樣風險（尚未逐頁改，使用者回報才處理）。
新寫列印功能請直接用本篇的 Blob＋`noopener` 寫法；ai-rules/16、ai-rules/09 的列印版面規則不變。
