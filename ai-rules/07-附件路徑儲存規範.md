# 附件／檔案路徑儲存規範
> 寫於 2026-07-13。對應 CLAUDE.md 鐵律第 5 條。
> 讀者：任何要新增或修改「檔案存 NAS/磁碟、路徑存 DB」相關功能的 AI session。

## 為什麼要有這條規則
2026-07-13 盤點全站附件/圖檔路徑功能，發現同一件事本專案存在兩種做法，換 NAS 硬碟或搬資料夾時下場完全不同：

- **情況一（禁止再新增）**：上傳當下把「根路徑設定值＋子資料夾＋檔名」組成**完整絕對路徑**，直接寫死存進 DB。讀取/下載/刪除時直接拿 DB 存的那條路徑用。→ 換 NAS 磁碟代號或搬資料夾後，就算改了網頁設定，**舊資料的 DB 紀錄還是寫著舊路徑，會找不到檔案**，且無法只靠改設定修復，須額外寫 SQL 搬資料。
- **情況二（本規則要求的做法）**：DB 只存**檔名**（`file_name`），不存路徑。讀取/下載/刪除時，用「當前設定值的根路徑」＋「即時算出的子資料夾」現場組出完整路徑。→ 換 NAS 代號或搬資料夾後，只要把「資料夾＋檔名」原封不動複製過去、改一個設定值，**舊資料立刻能讀**，不用動 DB。

## 規則本身
**任何新功能，只要牽涉到「檔案存在磁碟/NAS 上、路徑會變動（尤其可能對應到 NAS）」，一律採情況二寫法：**

1. 資料表**不存完整路徑**。只存：`file_name`（實際存檔檔名，可含 timestamp/亂碼避免碰撞）＋（若原始檔名要留存）`original_filename`。
2. 根路徑存在 `system_settings`（或該模組既有的設定表，如報價單的 `system_parameters`），**不要寫死在程式碼**。
3. 子資料夾名稱（通常是單號、料號等）**不要另外存一份路徑欄位**——它本來就是這筆附件關聯的單據自己的欄位（外鍵可查到），現場需要時用該單據的當前值現場算，不要快取成路徑字串存起來。
4. 寫一個該模組專屬的「路徑解析函式」，例如：
   ```php
   function xxxAttResolvePath($db, array $row): string {
       $root = rtrim(getSetting($db, 'xxx_nas_dir', '預設值'), '\\/');
       $sub  = 現場算出的子資料夾（通常＝單號，規則需與上傳時一致）;
       return $root . DIRECTORY_SEPARATOR . $sub . DIRECTORY_SEPARATOR . $row['file_name'];
   }
   ```
   所有「下載/預覽/刪除/is_file/readfile/unlink/加註浮水印」的地方都呼叫這個函式，**不要**在多處各自重複組路徑邏輯（子資料夾規則以後若要調整，才只需要改一個地方）。
5. UNC 路徑（`\\主機\分享\...`）比磁碟代號（`Z:\...`）穩定，新設定值預設建議直接用 UNC；但這條規則本身**跟用 UNC 或磁碟代號無關**——不管根路徑字串長什麼樣子，「現場組路徑、不存絕對值」才是重點。UNC 相關的既有陷阱（不要對 UNC 根目錄 `is_dir()`/`is_writable()` 預檢、反斜線轉義等）見 `Z槽改UNC_提示詞與邏輯.md`。

## 已經合規、可以直接抄的範例
- 業務追蹤圖片 `sales_track_images`（`src/store/store_Sales_Track_API.php`，設定鍵 `sales_nas_dir`）
- 料號附件 `part_attachments`（`Part_Attachment_API.php`，設定鍵 `part_attach_nas_dir`，含 30 天軟刪除清理邏輯）
- 技術備註圖片 `note_images`（`views/pages/master_data_management.php`，設定鍵 `notes_nas_dir`）
- 訂單變更單附件 `order_change_attachment`（設定鍵 `order_change_attach_dir`）

以下模組還是情況一寫法，**遷移工作正在進行，動手前先看這兩份文件的最新狀態，不要重複規劃**：

- 進度追蹤：`NAS路徑改造_修改紀錄.md`（專案根目錄）

涉及模組：QA 異常單附件（`qa_abnormal_attachments`）、CAR 矯正單附件（`car_attachment`）、公告附件（`live_event_file`）、IR 退貨附件（`ir_attachments`）。**在這些模組遷移完成前，若要新增這幾個模組的附件相關功能，一律比照情況二寫新程式（不要延用舊的絕對路徑寫法），避免遷移時要改的地方越滾越多。**

## 例外與地雷（動手前必看）
- 若「子資料夾名稱」所依據的單號/料號**建立後可能被改名**，現場重組路徑會找錯資料夾——動手前務必確認該單號是否不可變（查程式碼有無改名功能，或直接問使用者），不確定就問，不要假設。
- 純本機 `uploads/` 目錄（非 NAS）的暫存檔案不受本規則約束（本來就在專案內，不會因換 NAS 而受影響）。
- 純「即時掃描資料夾比對」用途（不存 DB，只在頁面載入時 `scandir()` 找料號對應圖檔，如 `bom_viewer.php` 等一批圖面檢視頁）不是本規則要處理的對象——那批路徑是直接寫死在程式碼裡，屬於另一類問題，不要混為一談。
