## 一、三件沒被問到、但對這個環境最重要的事

### 1. 這不是 git repo，而它應該是
目前唯一的後悔藥是手動 `.bak` 檔，只保護「單次修改」，不保護「一連串修改後發現三天前就改壞了」。
**建議向使用者提出**：在 `c:\MAMP\htdocs\EGsystem` 執行 `git init` + 每次修改後 commit（副作用只有多一個 .git 資料夾，不影響 Apache/PHP 運作）。使用者同意前，繼續嚴格執行 .bak 鐵律。另注意：`uploads/`、`*.sql`、`vendor/` 應進 .gitignore。

### 2. web root 裡躺著一個 15MB 的完整資料庫 dump
`EGsystem_20251218_173007.sql`（15.5MB）直接放在 htdocs 下，內網任何人打 `http://192.168.2.128/EGsystem/EGsystem_20251218_173007.sql` 就能下載整個資料庫（含 user 資料）。DB 憑證明文存在於 `src/common/_config.php` 與 `ai-rules/tools/sql.php`（後者是制度自建工具，已加 CLI-only 防護擋住 HTTP 存取，但憑證仍是明文；改密碼時兩處要同步改）。內網系統風險有限，但值得**主動提醒使用者**把 dump 移出 web root。未經使用者同意不要自行移動或刪除它。

### 3. `master_data_management.php`（1.5MB）是未爆彈
單檔 1.5MB 已超過任何模型能整體理解的範圍，每次修改都是在局部盲改。不要提議大重構（違反「不破壞既有功能」鐵律），但可以向使用者提議「新功能一律寫成獨立 include/API 檔，不再往巨檔裡加」。在使用者同意前，照鐵律 2 的巨檔流程操作。
