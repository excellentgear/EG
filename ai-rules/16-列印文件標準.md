> 會議記錄+KPI 頁、或簽到表+會議記錄+KPI 三合一)，一律改回**內文寫法**(`docNoMode='inline'`，緊接在該份文件內容尾端印，

## 一、大標題＝本公司全名（發票用），動態取、禁寫死

- 每份列印文件最上方**大標題＝本公司公司全名**，第二行＝文件名稱（如「外來文件清單」）。**一律分兩行印**（`.pt-head .co`＝大標題／`.pt-head .tt`＝副標題），**禁止合併成一行**，除非該文件本身有明確的公司紙本範本擺明就是合併一行（此時依範本為準，例：會議記錄 2-GM-05-01 的紙本範本印「公司全名-會議記錄」一行）——有紙本範本的文件才能例外，其餘一律兩行（2026-08-05 使用者明確要求，起因簽到表被誤依會議記錄的合併單行範本套用）。
- 公司全名的唯一來源：`customer_list.is_own_company = 1` 那筆的 `customer_full`（客戶全名·發票用；空則退 `customer`）。這筆資料在主檔管理（master_data_management）客戶頁維護，改公司名只改主檔、全站列印跟著變。
- **禁止把公司名寫死在頁面裡**（2026-07-30 供應商稽核已因此改過一次）。程式裡只允許 try/catch 的最後 fallback 字串。
- 可直接抄的取法（`src/store/ExternalDoc_API.php` 的 `extdoc_company_name()`、`src/common/vendor_audit_lib.php` 的 `vendor_audit_company_name()`）：
```php
$st = $db->query("SELECT customer_full, customer FROM customer_list WHERE is_own_company=1 LIMIT 1");
```

## 一之二、表頭（大標題下方那一行）＝已綁定 AS 文件的「表單名稱」，動態取、禁寫死

> 2026-08-03 補列（使用者明確要求，全站列印文件適用）。這裡的「表頭」**不是** table 的 `<thead>`，指的是大標題（公司全名）**正下方那一行標題文字**。

- 有綁定 AS 文件編號的列印文件，**表頭一律＝該 AS 文件的 `doc_name`（表單名稱）**，不可在頁面裡寫死標題字串。
  - 例：結構總覽綁定 `2-DC-01-01 文件管制總覽表` → 表頭自動印「文件管制總覽表」；日後表單改名只改 AS 文件主檔，列印跟著變。
- 三件事一次到位：**大標題＝公司全名（第一節）｜表頭＝綁定 AS 文件的表單名稱（本節）｜頁尾右下＝該 AS 文件的 `doc_no`（第三節）**——後兩者同一筆綁定資料，取 `doc_name` 與 `doc_no` 即可，不要各取各的來源。
- 未綁定時才退回頁面自訂的預設標題（如「AS 文件結構總覽」），並且右下角不印編號。
- 綁定值一律存設定（`system_settings` 或 `system_parameters`）只存 `as_document.id`，**禁止把編號/名稱字串存進設定**（改名或換版就對不上）。
- 可直接抄：`src/store/AS_Document_API.php` 的 `asTreeBoundDoc()`＋`views/ADM/as_document_management.php` 的 `#btnTreePrint`（結構總覽列印）。

## 一之三、AS 文件編號「綁定的做法」全站統一（後端 `asdoc_lib.php`＋前端 `eg_asdoc_picker.js`）

> 2026-08-03 新增（使用者明確要求：「AS 文件編號綁定方式每個頁面都不一樣，請幫我統一成可以填寫編號快速篩選出現列表的功能」）。
> 起因：AS 文件目前有 **163 份**，好幾個頁面的綁定 UI 只是一個長下拉，要用眼睛在 163 個選項裡找編號；
> 而且存放位置每頁自己決定、顯示格式每頁不一樣。**新頁面一律照本節做，不要再各自刻一份。**

**後端唯一實作點 `src/common/asdoc_lib.php`**（禁止各頁自己寫綁定的讀寫 SQL）：
```php
require_once __DIR__.'/asdoc_lib.php';
$doc  = eg_asdoc_get($db, '模組代碼');    // ['id','doc_no','doc_name',...]；未綁定回 null
$docs = eg_asdoc_list($db);               // 給前端挑選用（id / doc_no / doc_name）
eg_asdoc_save($db, '模組代碼', $docId, $userName);   // $docId=0＝解除綁定
```
- 綁定值統一存 `system_parameters(param_group='AS_DOC_BIND', param_key=模組代碼)`，**只存 `as_document.id`**（禁存編號/名稱字串）。
- 既有模組原本存在別處的，登記在 `EG_ASDOC_LEGACY` 當回退來源即可，**不必搬資料**。

**前端唯一實作點 `resource/js/eg_asdoc_picker.js`**（禁止各頁自己刻綁定 UI）：
```html
<script src="../../resource/js/eg_asdoc_picker.js?v=<?= @filemtime(...) ?>"></script>
```
```js
EGAsDoc.open({docs: 清單, current: 目前id, title:'…', onSave: function(id, doc){ /* 存檔 */ }});
EGAsDoc.label(doc)   // 顯示字串統一為 '2-SM-01-05（訂單變更紀錄表）'
```
- 固定行為（全站一致）：**輸入框打編號或名稱即時篩選**（多關鍵字空白分隔＝每個都要命中）→ 清單直接點選 →
  Enter 只剩一筆時直接選起來 → Esc/點遮罩取消；**目前已綁定的那一筆永遠留在清單裡**（篩選不會把它洗掉）。
- **禁止**只放一個 `<select>` 讓使用者自己捲；也不要再自己寫「關鍵字 input + 手工 filter」那一段（會各頁行為不一致）。

**綁定後畫面上的「表頭／表尾」欄位一律唯讀反灰**：表頭＝`doc_name`、頁尾右下＝`doc_no`，
都由綁定推導，**不可讓使用者手填**（手填就會和 AS 文件主檔對不上，違反本檔第一之二節）。
標準示範：`views/Sales/NewOrder_Track.php` 的「訂單變更設定 → 訂單變更列印文件（AS 文件綁定）」。

## 二、頁碼＝左下角「第 X 頁／共 Y 頁」，多頁才顯示

- 統一印在**頁尾左下角**，格式「第 X 頁／共 Y 頁」。
- 一律用 `@page { @bottom-left { content:'第 ' counter(page) ' 頁／共 ' counter(pages) ' 頁'; } }`，由**列印引擎在列印當下計算**——換印表機頁數變了頁碼也自動正確。禁止 JS 自己算頁數寫進頁面。
- 「多頁才顯示」的判斷：以 A4 概算 `document.body.scrollHeight > (297-頁邊mm)*96/25.4*0.92` 才動態插入上面那條 style。這個量測**只決定頁碼顯示與否，完全不影響分頁**，不違反 print_pagination 鐵則（quotation_list_test.php 既有作法）。橫式列印高度換算要用 210（A4 短邊）而非 297。
  可直接抄：`meeting_record.php` 的 `egPrintWindow(title, bodyHtml, extraCss, docNo, landscape, pageCount, showPageCounter)` 第7參數（2026-08-06 補上，之前這支共用函式一直沒做這個判斷，不管內容長短一律印頁碼，已修正）；合併多份獨立文件成一次列印工作時明確傳 `showPageCounter=false` 整個關掉。

## 三、文件編號（AS 表單編號）＝頁尾右下角

- 有綁定 AS 文件編號的報表/表單，`doc_no` 一律印在**頁尾右下角**：`@page { @bottom-right { content:'2-XX-XX-XX'; } }`（每頁都有，不是只有最後一頁）。
- 編號來源一律走 `as_document` 綁定（各模組自己的綁定設定，如 system_parameters `EXTERNAL_DOC/as_doc_id`），禁止寫死編號字串。
- **印出的編號後方要直接附加版次 `current_version`，但限定「四階文件」才適用（2026-08-05 使用者明確要求收斂範圍）**：`as_document.doc_level='四階'`（表單/記錄表）的綁定文件，無版次時只印編號本身（例 `2-MM-01-11`），有版次時緊接編號後方不加分隔符（例版次 B → `2-MM-01-11B`）；**一階（手冊）／二階（程序書/標準書）一律只印 `doc_no`，不附加版次**——這兩階文件是整份改版才變動版次，不像表單那樣需要逐張辨識是第幾版，母文件本身也不可能是四階（見 `AS_Document_API.php` 的 `asValidateParent()`），版次資訊已在文件本體改版履歷可查，頁尾不必重複印，附加了反而混淆「這是第幾版程序書」。
  - 後端組字串一律用 `asdoc_lib.php` 的 `eg_asdoc_no($doc)`（內建四階判斷；`$doc` 需含 `doc_no`＋`doc_level`＋`current_version`——查詢 SQL 記得把 `doc_level` 一起 SELECT 出來，漏了會判斷不到誤判成不附加），不要只取 `doc_no` 就印出去，也不要自己重寫一次判斷式。既有各模組專用取號函式（`training_lib.php` 的 `training_as_doc_no()`、`vendor_audit_lib.php` 的 `vendor_audit_bound_asdoc()`）內部已比照同一套四階判斷邏輯。
- 動態塞進 content 字串前先把 `'` 與 `\` 濾掉（`String(docNo).replace(/['\\]/g,'')`），避免撐破 CSS。

## 三之二、簽章（含代理人代簽「代」字）

> 2026-08-03 制定（使用者明確要求，全站列印文件一體適用）。起因：線上檢驗記錄表列印版只印人名，紙本簽核看不出是誰、哪一天核的。

- **簽章欄不可只印人名**，一律用共用元件 `resource/js/eg_stamp.js` 的 `EGStamp.stamp(name, date, isDeputy)` 產生**帶日期的印章**（有上傳掃描章的人自動改用實體章去背圖＋動態日期帶，沒上傳的人用 SVG 回墨印）。頁面要先載入 `eg_stamp.js`，並把本公司全名放進 `window.__ownCompany`（同第一節的取法）。
- **簽章日期的認定**：已存檔的單據一律用**該單據的業務日期**（檢驗記錄表＝檢驗日 `check_date`），不是列印當下的日期；尚未存檔的現場列印才用今天。同一份文件的所有簽章共用同一套認定方式。
- **印章自帶日期，所以簽章欄旁邊不要再開一個「日期」欄**；文件本身的日期印在資料表格**最右上角**的格子。
- **代理人代簽必須看得出來**：簽章右下角加「**代**」字（`EGStamp.stamp(name, date, true)`，元件已內建）。代理人一律由 `src/common/delegate_lib.php` 的 `eg_resolve_signer()` 解析（ai-rules/11），**禁止各頁自己猜代理人**；解析出來的人 ≠ 原簽核人時 `is_delegated=true`，就是要蓋「代」字的情況。
- **可選簽章人的名單怎麼來**（2026-08-03 定案）：不要為了某一張表單去 `org_role_setting.php` 加一個「某某表單簽章人」角色——一個部門常有課長／副課長／組長多位主管，表單層級的「這張單該誰簽」屬於該模組的設定，塞進全站組織綁定會愈長愈雜。正確做法是**部門取自組織角色綁定、人由模組自己挑**：`eg_org_dept_ids($db,'qc_dept')` 取部門（含子部門）→ `eg_org_dept_managers($db,$ids)` 取該部門**所有主管**（＝職稱在 `position_level` 有 level 者，已依職級由大到小排序）→ 交給 `eg_people_list()` 產生下拉（只列在職、標記長期請假、顯示職稱）。只需要自動推算「唯一一位部門主管」時才用 `eg_org_dept_manager()`。
- **自動核可**（系統代替主管蓋章）要有**設定開關＋指定核可人**，並用獨立功能碼授權哪些角色可改（例：線上檢驗 `qc_print_approve_setting`），設定值存 `system_settings`。沒啟用時該欄留白給人手簽。
- **簽核流程若是 A4 橫式，簽章欄由左到右固定「核准、審核、製表」**（2026-08-14 使用者明確更正，起因 `review_form.php` 一開始做反了）：**最左側＝核准**（或本張單上的最高簽核人員）、**中間＝審核**（與製表同部門主管，或設定好的部門內主管）、**最右側＝製表**。只有兩欄（沒有審核關卡）時仍照第四之五節「兩格要分三等分、中間留空」處理，核准維持在最左、製表維持在最右。

  **⚠️「單頁不可印頁碼」的根因排查**：判斷「這份文件會不會分頁」一律靠 JS 在 `onload` 後量 `document.body.scrollHeight`（見四之五、四之六），**`document.write()` 開頭一定要帶 `<!DOCTYPE html>`**——漏寫會讓列印視窗落入 Quirks Mode，`<body>` 內容不滿版時會被撐滿整個視窗高度，`scrollHeight` 永遠量出接近視窗高度而非實際內容高度，導致單頁文件也誤判成「會分頁」而印出「第1頁／共1頁」（2026-08-14 `review_form.php`／`hr_position_forms.php` 皆曾漏寫，`training_record.php` 是原本就寫對的參考範例）。新開列印視窗一律檢查這行有沒有 `<!DOCTYPE html>`。

## 三之三、多份文件「合併列印」時的 AS 編號定位（2026-08-06 制定，`meeting_record.php` 除錯六輪後定案）

> 起因：`meeting_record.php` 曾經想把「簽到表＋會議記錄＋KPI」三份文件合成一次列印工作（`window.print()` 一次印出多頁），
> 結果 AS 編號在 `position:fixed`（釘頁角，正確但跨頁會疊字）與內文寫法（不疊字，但離頁角有距離）兩個方案之間來回，
> 兩個都不是「完全正確」的解——`position:fixed` 元素在 Chrome 列印中的作用範圍是**整個列印工作**，不是它寫在 HTML 的哪個
> `page-break-after` 區塊；只要同一次列印工作混了不同文件（各自不同編號、或某頁根本沒有編號），所有 `.as-doc-fixed` 都會疊在同一頁角。

**鐵則：AS 文件的「一頁一份、位置正確」與「多份文件一次列印」兩者不可兼得，優先保正確，不要為了省點擊次數犧牲編號位置。**

- **一個列印按鈕只印一份文件**（一種 AS 編號，或完全不需要編號如 KPI 頁），不要提供「一次列印全部」的合併按鈕。使用者要看多份文件時分別點按鈕列印即可。
- 這樣每個列印工作從頭到尾只對應同一組編號，`position:fixed` 才能安全使用（見第三節，`.as-doc-fixed{position:fixed;right:...;bottom:...;}`），不必再判斷「這次列印要用內文寫法還是 fixed」。
- 若某文件內容多到自己溢出成 2 頁以上也沒關係——同一份文件本來就該每頁都印同一組編號，`position:fixed` 在這種情境下沒有疊字風險（風險只在「同一次列印工作混了不同文件」時才會發生）。
- 可直接抄：`meeting_record.php` 的「列印會議記錄」/「列印空白簽到表」/「列印簽到表」/「列印出貨目標達成率」四顆各自獨立的列印按鈕（`printMeetingRecord()`/`printBlankSignSheet()`/`printSignedSignSheet()`/`printKpiOnly()`），已移除原本的「列印完整紀錄」合併按鈕。

## 三之四、版次要依「業務日期」回推，不是一律印現在最新版（2026-08-06 制定，使用者明確要求）

> 起因：使用者發現列印舊單據時，AS 編號後面附加的版次一律是**現在最新版**（`as_document.current_version`），
> 跟被印文件本身的日期無關——例如會議記錄 AS 表單 A 版 2025.01.01 生效、B 版 2025.12.09 生效，理論上列印
> 2025.09.08 的會議紀錄要顯示 A 版、列印 2025.12.09（含）之後的會議紀錄要顯示 B 版（改版生效日當天啟用新版），
> 但改版前全部模組都是直接讀 `current_version`，不會回推。

**鐵則：印一份「有自己業務日期的單一筆單據」時，版次要回推到「該單據業務日期當時生效的版次」，不是印現在最新版。**

- **業務日期認定（優先序，比照第三之二節簽章日期的精神）**：①單據本身的日期欄位（會議日期/報價日期/檢驗日期…）②單據沒有日期欄位才用單據建立日期 ③尚未存檔的新單據預覽列印用列印當下。
- **改版生效日**存在 `as_document_version.revised_date`（該筆版次的改版生效日）；判斷邏輯＝該文件 `revised_date <= 業務日期` 中**最新一筆**的 `version` 就是當時生效的版次，從生效日當天起算。
- **唯一實作點**：`asdoc_lib.php` 的
  - `eg_asdoc_version_asof($db, $docId, $bizDate)` — 回推版次字串（可能是空字串＝當時尚無版次；回傳 `null` 才代表該文件完全沒有版本履歷資料，退回 `current_version`）
  - `eg_asdoc_no_asof_id($db, $docId, $bizDate)` / `eg_asdoc_no_asof($db, $module, $bizDate)` — 組出完整編號（含四階版次附加判斷），**印單一筆有業務日期的單據一律呼叫這兩支之一，不要再呼叫 `eg_asdoc_no($doc)` 印「現在最新版」**。
  - `$bizDate` 傳 `null`／空字串＝視為今天，行為等同舊版 `eg_asdoc_no()`（回推「現在最新版」），所以此改動對「本來就該印現況」的清單型列印無副作用。
- **哪些列印適用、哪些不適用**：

- **既有模組相容表**（2026-08-06 首次規則化，非一次全站補完；後續有人動到某模組列印時要順手比照本節補上）：

## 三之五、批次列印「多筆各自獨立文件」的正確做法（2026-08-12 制定，`type_id_ctrl_doc.php` 已實作，`td_dev_eval.php` 比照）

> 跟第三之三節的「一個列印按鈕只印一份文件」**不衝突**：第三之三節禁止的是把多份文件**合併成同一次 `window.print()`**；
> 本節講的是使用者想要「依目前搜尋/篩選結果，一次把全部符合條件的單據都印出來」的正當需求，做法是**依序觸發多次、各自獨立的單筆列印**，
> 不是把內容合併成一份文件。

**鐵則：批次列印＝逐筆呼叫既有的單筆列印函式，每筆各自開一個新視窗、各自獨立算頁次；不做任何內容合併。**

- 單筆列印函式加一個可選的 `onDone` callback 參數（`function printDoc(id, onDone){...}`），開完視窗、`document.close()` 後 `if (onDone) setTimeout(onDone, 500);`（留 500ms 讓瀏覽器有時間把視窗開起來，避免彈出視窗被瀏覽器節流）。
- 批次按鈕依目前畫面上的搜尋/篩選結果（不是全部資料庫資料）取得 id 清單，用遞迴 `next()` 依序呼叫 `printDoc(id, next)`，全部印完才 alert 完成。
- **筆數較多時**（門檻可用 `PRINT_ALL_BATCH_THRESHOLD`，已用頁面抓 15）要先 `confirm()` 提醒使用者「數量較多、瀏覽器可能跳出快顯封鎖提示」，使用者確認才開始跑；不要無聲一次炸開幾十個視窗。
- **每份文件自己算頁次、只有一頁不顯示頁碼**：因為每筆都是各自獨立的 `window.print()` 工作，第四節骨架裡原本就有的「`scrollHeight` 超過一頁高度 92% 才動態加頁碼 `@page @bottom-left` 樣式」邏輯完全不用改，批次觸發時自然每份文件各自判斷、互不影響。
- 可直接抄：`views/TD/type_id_ctrl_doc.php` 的 `printDoc(id, onDone)` + `$('#btnPrintAll')` 點擊事件（`PRINT_ALL_BATCH_THRESHOLD`），或 `views/TD/td_dev_eval.php` 的同一套實作。

## 四之二、取消瀏覽器自己的頁首／頁尾（2026-08-03 使用者明確要求，全站列印一體適用）

列印出來最上面那條「網頁標題　about:blank」、最下面那條「日期　網址」**是瀏覽器加的，不是我們的內容**，正式表單上出現這些字很難看，一律要拿掉。

- 做法：**`@page { margin: 0 }`**，版面留白改用 `body{padding:10mm 8mm 12mm}`。頁邊界為 0 時瀏覽器沒有位置畫自己的頁首/頁尾，就不會印出來（不必叫使用者自己去列印設定取消勾選「頁首及頁尾」）。
- 代價：`margin:0` 之下 `@page` 的 margin box（`@bottom-left`/`@bottom-right`）也沒有空間，**第二、三節的頁碼與文件編號要改用 `position:fixed` 的元素**印在每一頁：
  ```css
  .pt-foot{position:fixed; right:8mm; bottom:5mm; font-size:9pt; color:#333;}  /* 文件編號 */
  ```
- 頁碼：`position:fixed` 拿不到 `counter(page)`。**單頁報表不印頁碼**；確定會多頁的文件才保留原本的 @page margin box 寫法（此時瀏覽器頁首頁尾就得靠列印設定關閉，二選一）。判斷原則：紙本表單（計畫表、明細表、簽到表）優先「乾淨版面」；長清單型報表優先「頁碼」。
- 欄位多的橫式報表（例如 12 個月份欄）用 `@page{size:A4 landscape}`，不要硬塞直式。

## 四之三、排版：標題階層與欄寬（避免中文被擠成一長條）

- **大標題（公司全名）22px 粗體、副標題（表單名稱）16px 粗體**，兩者字級要拉開才有層次；副標題下方可放一行 11px 的補充資訊。
- 表格一律 `table-layout:fixed` ＋ `<colgroup>` 明確配置每欄百分比寬度，文字欄加 `word-wrap:break-word`。
  **不要只寫 `width` 在 `<th>` 上**：欄一多，瀏覽器會把中文欄壓到剩一個字寬、整欄變成直排一長條（教育訓練計畫表踩過）。
- 文字欄（課程名稱、對象、單位）左對齊；數字/代號欄置中。

## 四之四、字型統一（2026-08-04 使用者明確要求，全站列印一體適用）

全站列印文件一律用同一套字型堆疊，直接照抄第四節骨架裡的那一行，**不要各頁自己選字型或漏掉中文名備援**：
```css
body{font-family:"Microsoft JhengHei","微軟正黑體",sans-serif;}
```
- `"Microsoft JhengHei"` 是英文字型名稱、`"微軟正黑體"` 是同一套字型的中文別名——同時列兩個是防呆：作業系統/瀏覽器對字型名稱比對不到英文名時，中文別名還能命中，不會退到系統預設字型（通常是新細明體，筆劃較細、掃描/影印後可讀性差）。
- 檢查過本頁既有列印曾出現過的落差：`.pt-head`/`.pt`/`.pt-sign`（`egPrintWindow()`）已是這個堆疊；`printSignSheet()`／`printRecord()` 原本各自開新視窗、字型堆疊各寫一份且有缺中文別名或整段沒用共用視窗，已一併改用 `egPrintWindow()` 統一。**新增列印功能一律呼叫 `egPrintWindow()`，不要再開一個 `window.open()` 自己兜一份 CSS**——字型、公司名、頁碼/文件編號寫法才不會一頁一個樣。

## 四之五、簽章版面鐵則（2026-08-04 使用者明確要求，全站有簽章的列印文件一體適用）

> 起因：供應商稽核計劃／記錄表列印版面跑掉，簽章被切到下一頁；且只有兩個簽章欄並排時比例很怪（兩個章擠在一起、旁邊一大片空白）。

1. **簽章一定要跟表單內容在同一頁，禁止被分頁切開**：簽章列所在的 `<table>`／容器一律加 `page-break-inside:avoid`（或等效寫法），並確保簽章前面的內容（表格、圖表、摘要文字）**總高度**在排版時就要抓夠緊，不要讓簽章列被擠到下一頁去。設計新列印版面時，**先假設簽章一定要跟主要內容同一頁**去抓每個區塊的高度／字級，不要等印出來才發現超版。
2. **簽章列只有兩格（例如「核准」＋「製表」）時，版面要分成三等分**：第一格放第一個簽章、第二格留空、第三格放第二個簽章（`<td style="width:33%">章</td><td style="width:34%"></td><td style="width:33%">章</td>`），不要只用兩欄各佔一半——兩個章緊貼中線視覺上比例會很奇怪。三欄以上（如「核准／審核／製表」）維持原本平均分配即可，不受本條限制。
3. **確定會超過一頁的「清單型」文件（如稽核計劃、合格供應商清冊這種逐列印很多廠商的表）**：**禁止用 `position:fixed` 讓大標題／簽章重複出現在每一頁**——這是 2026-08-05 供應商稽核計劃列印「版面跑掉」的根因（不同印表機引擎對 fixed 定位配合分頁的算法不一致，同一份文件在不同印表機呈現不同）。正確做法是**逐頁手動分段**（比照 `printEvalAll()`／稽核計劃列印的寫法）：
   - 依固定筆數（例如每 16 家一頁）把資料切成幾個 chunk，每個 chunk 各自組一段「大標題＋表格＋（最後一段才加）簽章列」的 HTML，中間用一般文件流排版（不用 `position:fixed`/`absolute`），除了最後一段都在外層 `<div>` 加 `page-break-after:always`。
   - 頁碼交給 `@page` margin box 的 `counter(page)`/`counter(pages)`（見本檔既有列印骨架的 onload 偵測邏輯），不要土法手刻。
   - **筆數上限務必實際換算是否真的塞得進一頁**，不要只憑直覺訂數字：橫式 A4 扣邊界後可用高度約 182mm（≈688px，公式 `(210-上邊界-下邊界)*96/25.4`），把大標題（約 80px）＋表格每列高度（含 padding／框線，通常 25~30px／列）＋簽章列（圖章實際 91px，不是隨便設的 `min-height` 佔位值）都算進去，總和必須留有餘裕（建議抓可用高度的 85~90% 為上限，不要壓線）。若算出來會超版，**縮小表格列高／字級**（例如加一個專屬 class 覆寫 `padding`/`height`，不要動到其他頁共用的 `.pf` 樣式），而不是隨意調降筆數上限（筆數常是既定的業務需求）。

## 四之六、同一次列印工作要混排直式／橫式頁（例如查核表直式＋記錄表橫式合成一份列印工作）

**CSS「具名頁」(named page) 可以穩定達成，不要因為怕不可靠就拆成好幾個列印視窗**——`meeting_record.php` 的「列印完整紀錄」（簽到表直式＋會議記錄/KPI橫式）與 `vendor_audit.php` 的「一次印全部文件」都已用這個技巧且實測穩定，2026-08-06 前一版誤判「同一列印工作中途切換方向不可靠」把它拆成兩個視窗，是沒有先查證自家 codebase 已有成功先例就下結論。

寫法（`writePrintWindow()`/`egPrintWindow()` 這類共用骨架都應該接受一個 `extraCss` 參數）：
```css
@page{size:A4 portrait;...}                 /* 預設頁：多數內容用這個方向 */
@page va-landscape{size:A4 landscape;...}    /* 具名頁：少數要另一個方向的內容用這個 */
.va-landscape-page{page:va-landscape;}       /* 套在需要橫式的那段內容外層 div 上 */
```
每份子文件各自的 AS 文件編號，分別寫在對應那個 `@page` 規則（預設頁或具名頁）自己的 `@bottom-right`，不會互相覆蓋；子文件之間仍用一般的 `page-break-after:always` 分頁，不需要額外處理。

## 四之七、圖章／固定尺寸元素的列印 CSS 不會自動繼承，新增列印路徑務必自查

任何**新的**列印輸出路徑（新開一個 `window.open()`、或（不建議但如果真的要）直接列印畫面上的 DOM），凡是內容含圖章，**都要自己明寫**這條規則，不能假設瀏覽器/畫面顯示的樣式會帶過去：
```css
.stamp-wrap svg,svg.car-stamp{width:91px;height:91px;-webkit-print-color-adjust:exact;print-color-adjust:exact;}
```
（尺寸依據見 `ai-rules/18-簽章圖章規則.md` 第6條）2026-08-05 供應商稽核記錄表曾經漏加這條，圖章印出來退回畫面顯示的預設尺寸（76px），比規定小很多。**收尾前用這份清單自查一次**：①圖章 91px CSS 有沒有寫 ②固定列數的清單型文件有沒有照四之五第3點實際換算高度 ③混排橫直式有沒有用四之六的具名頁而非拆視窗或 `position:fixed`。

## 五、既有頁面

既有列印頁（如 quotation_list_test 頁碼在 @bottom-center）不強迫回頭改（鐵律4），但**新做或大改列印版時**一律改到本標準：大標題公司名動態取、頁碼左下、文件編號右下。
