# 列印與簽核紀錄 — 全站一律自動入帳
> 最後修改：2026-08-21 — 建立。使用者明確要求：「之後列印與簽核都要自動記錄到這邊」。
> 讀者：要新增／修改**任何會列印的頁面**或**任何有簽核的模組**的 AI session。

查詢頁面：`views/admin/print_sign_log.php`（選單「測試功能」底下，名稱「列印與簽核紀錄」）。
唯一實作：`src/common/print_log_lib.php`｜API：`src/store/PrintSignLog_API.php`｜前端：`resource/js/eg_print_log.js`。

---

## 1. 兩條鐵則

**鐵則一：會列印的頁面一律留列印紀錄。**
只要頁面上有任何「按了會送到印表機」的按鈕（`window.print()` / `contentWindow.print()` / `egPrintWindow`），
就必須在**使用者按下列印的那個入口**呼叫一次紀錄。**禁止各頁自己再開一張列印紀錄表**
（`quotation_print_log`、`pfmea_print_log` 等五張是本規則出現之前就存在的，唯讀彙整、不搬家，新的不准再開）。

**鐵則二：簽核紀錄一律走共用的 `approval_record`。**
送審／核准／駁回一律呼叫 `src/common/approval_lib.php` 的
`eg_approval_submit()` / `eg_approval_decide()` / `eg_approval_latest()`。
模組自己另建 `xxx_signoff` / `xxx_cosign` 表存簽核事實的，紀錄頁**查不到**，等於這個模組沒有可追溯性。

## 2. 列印紀錄怎麼掛（三步，五分鐘）

1. **登錄來源**：`print_log_lib.php` 的 `eg_print_sources()` 加一列
   `'代碼' => ['label' => '顯示名稱', 'page' => 'views/xx/yyy.php', 'kind' => 'attachment|form']`。
   加了才會出現在紀錄頁的篩選下拉與「涵蓋範圍」說明。
2. **載入共用檔**（放在 `custom.min.js` 之後）：
   `<script src="../../resource/js/eg_print_log.js?v=<?= @filemtime(__DIR__.'/../../resource/js/eg_print_log.js') ?>"></script>`
3. **在列印入口呼叫一次**：
   ```js
   EGPrintLog.record({
       source: '代碼', doc_name: '檔名或單據標題',
       doc_kind: 'attachment',            // 或 'form'
       ref_table: 'part_attachments', ref_id: 123,   // 選填
       part_no: 'RC105-N03-A', note: '作廢附件'       // 選填
   });
   ```
   後端要記的話用 `eg_print_log_add($pdo, [...])`（同一組參數）。

### 三個容易做錯的地方
- **一次列印只能記一筆**：有「主要方式失敗就退回另一種列印」的頁面（如批圖編輯器 PDF→向量→快速），
  只在**使用者按的那顆按鈕**記，退路函式不可各記一次，否則一次列印變三筆。
- **記的是「按下列印」不是「印出來」**：瀏覽器不會回報使用者在列印對話框按了確定還是取消，
  所以取消也會留一筆。這是刻意的（否則按取消就能規避紀錄），要寫進該頁的使用說明。
- **紀錄壞掉不可以擋住列印**：`eg_print_log_add()` 任何例外都只回 0；前端 `EGPrintLog.record()` 送出即忘、
  不等回應、不跳錯誤。列印是現場作業，不能因為記錄失敗就印不出來。

## 3. 登入電腦（IP → 電腦名稱）

`eg_client_ip()` 取 `REMOTE_ADDR`（**不信任 X-Forwarded-For**，可偽造）；
`eg_client_host($pdo, $ip)` 反查電腦名稱，快取在**既有的 `ip_hostname_cache`**（與 `audit_log_report.php` 共用同一張，不另建）。

解析順序與四個坑：
1. **本機要先判掉**：nbtstat 問自己一定回「找不到主機」。判定要用 `gethostbynamel(gethostname())` 取本機所有區網 IP，
   只比 `SERVER_ADDR` 會漏掉（Apache 可能繫在別的位址）。
2. **nbtstat 的中文欄位是 Big5**，PHP 讀進來是亂碼，**不可以**靠「唯一／群組」那一欄判斷；
   要抓 ASCII 的服務代碼：`<20>` 優先，退而取**第一個** `<00>`（後面的 `<00>` 是 WORKGROUP 群組名）。
3. **DNS 反查會撿到 hosts 檔的假名字**（`host.docker.internal`、`localhost`），一律過濾掉，寧可只顯示 IP。
4. **查不到也要快取**：關機／不回應的機器 nbtstat 會等好幾秒。查得到快取 30 天、查不到快取 1 天。

## 4. 簽核紀錄的文件名稱

`approval_record` 只存 `module + entity_id`，看不出是哪一份文件。
在 `eg_sign_modules()` 補一列，紀錄頁就會顯示得懂：

```php
'模組代碼' => ['label' => '單據種類', 'page' => 'views/xx/yyy.php',
               'table' => '主檔表', 'pk' => '主鍵欄',
               'name_sql' => "CONCAT('報價單 ', t.quote_no)",   // 別名固定 t
               'join_sql' => "LEFT JOIN ...",                    // 選填
               'date_sql' => 't.quote_date'],                    // 業務日期，沒有就留空
```
沒補的模組**不會漏掉**，只是名稱退成「模組代碼 #id」。以年度為 entity_id 的（如年度計畫）用 `entity_is_year` + `name_fmt`。

### 自動簽核
自動簽核（ai-rules/21）產生的紀錄**一樣要收進來**，但
**畫面、列印、匯出一律不可出現「自動簽核」字樣**（使用者明確要求）。
`print_log_lib.php` 與 API 刻意完全不輸出 `is_auto` 之類的旗標，維護時不要「順手加回去」。

## 5. 涵蓋範圍一律即時算，不放寫死清單

`eg_print_coverage()` 掃 `views/` 底下每支 .php：有列印呼叫的算「會列印」，
檔案裡有 `EGPrintLog` / `eg_print_log_add(` 的算「已掛紀錄」。
**判定看的是檔案裡真的有呼叫，不是看它有沒有登錄在 `eg_print_sources()`**——
只憑登錄表判定，會在「登錄了卻忘了掛」時自稱已涵蓋，說明頁就變成假的。

`eg_sign_coverage()` 查 `approval_record` 實際有的 module（已涵蓋），
再掃資料庫裡其他看起來是簽核事實的資料表（未涵蓋）。
表名比對要排掉 `design`／`assign`／`attendee`——那是「設計」「指派」「簽到」不是「簽核」，
純用 `LIKE '%sign%'` 會把 `design_notes`、`roster_assignment` 當成漏網的簽核表。

**新增模組後不必回頭改這份清單**，它會自己更新；改壞了才要回來看這一節。

---

## 6. 權限

`roles.module = 'print_sign_log'`：`psl_admin`（紀錄管理）／`psl_view_all`（紀錄檢閱）。
**沒有角色的登入者仍看得到「自己的」紀錄**（本人的足跡，不是別人的）；
限制在**後端** `pslFilters()` 強制把 `user_id` 綁成本人，不是只在前端隱藏（鐵律8：不做半套）。
