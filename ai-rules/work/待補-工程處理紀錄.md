| `src/common/bom_progress_lib.php` | BOM 逐關製程（與 personal_task 共用，唯一實作） |

選單登記在「測試功能」底下（`system_module_pages` id 152），角色三個
（`eng_log_edit` 使用／`eng_log_view_all` 檢閱／`eng_log_admin` 管理員）。

## 五、順手發現、但沒有擅自改的共用檔問題

`resource/js/eg_input_rules.js` 第 435 行的 MutationObserver 會對**動態產生的任何 select**
長出打字篩選框，沒有比照初次掃描（第 424 行）檢查 `data-eg-filter`：

```js
if (n.tagName === 'SELECT') egFilterEnhance(n);          // ← 少了 data-eg-filter 檢查
```

症狀就是「翻頁鈕旁邊莫名多一個和上方關鍵字重複的搜尋框」。
本頁已用 `data-eg-skip` 迴避並在程式碼註記原因。
**要不要統一修正是使用者的決定**——改了會讓其他頁面現在意外長出來的篩選框消失，
影響所有載入此共用檔又用 JS 產生 select 的頁面（35 支以上）。

## 六、本模組踩過、值得記住的坑

- **`html` 的 `font-size` 是 10px**（Gentelella 的 `custom.css`），所以 CSS 裡的 `rem`
  只有預期的 62.5%。本頁一度把回覆日期欄寫 `9.5rem`，實際只有 95px、只露得出年份。
  **這一頁已全面改用 px**，其他頁面要注意同一件事。
- **`.ac-list` 不可以用 `position:absolute`**：跳窗的 `.m-body` 是 `overflow:auto`
  的捲動容器，會把下拉整個裁掉，畫面上就是「打了字卻沒有清單可以選」。
  測試只數 DOM 節點數抓不到，要驗 `elementFromPoint` 真的可見。
- **兼任職務不可以事後回推**：回推一律取職級最高那筆。實測陳俊宏同時是
  「董事長室 董事長」與「總經理室 總經理」，回推永遠只會對其中一個。
  已改成選定當下就把部門職稱記進 `eng_log_item.target_post` / `eng_log.proposer_post`。
- **出貨／退貨用料號搜尋不可以寫成相關子查詢**：`is_list` 有 37,745 列，
  對每一列再掃一次整張表會直接把請求拖到逾時（實測 >90 秒）。
  改成先查 `d_setting` 取 `d_id` 再用 `IN` 過濾，0.09 秒。
- **`bom.d_id` 與 `order_track.d_id` 是料號「文字」不是 int FK**，真正的是
  `bom.d_setting_id` 與 `order_track.d_id_ID`，但分別有 81%／56% 是空的。
  故 `el_resolve_part_id()` 採 int FK 優先、料號文字唯一命中才回退，
  有歧義時寧可不連結也不亂猜（`d_setting` 有 1,661 個重複料號字串）。
