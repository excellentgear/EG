### ★ 2-1（最優先，卡在使用者決策）會議紀錄出席人員「多職務」怎麼列

**現況**：稽核小組是「一筆職務一列」（例：2025 年度 11 筆職務／9 位成員，何沐桐＝生管組組長＋技術課工程師，吳仁隆＝採購組組長＋業務課經理）。
自動建立的會議紀錄**一人只列一次**，且只印**名單上排在前面的那個職務**（`meeting_create` 內 `$push` 依 user_id 去重）。
→ 使用者回報「自動建立的會議紀錄出席人員跟我設定的稽核小組成員沒有吻合」。

**已查證：人員本身完全吻合**（逐人比對 9/9，部門職稱全同）。差別只在 **11 筆 vs 9 列**。

**使用者的回覆（尚未定案，這是下一步要處理的第一件事）**：
> 「希望是多職務合併顯示，但會跟原本會議記錄內不同，這樣還會建議這樣改嗎?」

**我（上一個 session）的建議＝不要直接把合併字串寫進 `meeting_attendee`**，理由三點，請先跟使用者確認再動手：

1. `meeting_attendee.dept_name` / `position_name` 是**單一值欄位**，簽到表與**圖章**都直接吃它。
   圖章模板 schema 是 `{部門} {姓名}`，塞「生管組 組長／技術課 工程師」會讓章面爆版。
2. 會直接在 `meeting_record.php` 建立的一般會議（產銷會議等）仍是單一職務，**同一張表兩種格式**。
3. 真正要解決的是「使用者看不出來為什麼 11 變 9」，那是**顯示與說明**問題，不是資料結構問題。

**建議的替代做法（三選一，請使用者拍板）**：
- (a) 維持一人一列，但在**稽核小組畫面**明確標出「這 2 位有兩個職務，會議只會列一次，會用排在前面的那個」，並讓使用者可拖曳／指定「會議代表職務」。
- (b) `meeting_attendee` 加一個**純顯示用**欄位（例 `alt_posts`）存其餘職務，只在會議紀錄的出席名單顯示，**簽到表與圖章不吃它**。
- (c) 使用者若堅持合併字串，就只合併 `dept_name`／`position_name` 的**顯示**，但要同步確認簽到表與圖章版面（需實測列印）。

**相關位置**：`src/store/InternalAudit_API.php` 的 `case 'meeting_create'`（`$push` 去重與 `$att` 寫入那段）。

### 2-2 會議紀錄建立後，改了稽核小組**無法重新同步**

`meeting_create` 對「已經連結過」的案件會直接回傳既有會議、**不重建出席人員**（點開即刷新鐵則，避免重複建立）。
所以「先建會議 → 再改小組」時，會議上的人是舊的，畫面上沒有任何辦法重新套用。

- 目前的繞路做法：在稽核通知單按「解除連結」再按一次自動建立。
- 建議：在稽核通知單的會議紀錄區加一顆「**依目前小組重新帶入與會人員**」（只改 `meeting_attendee`，不動會議本身與已簽到狀態；已簽到的人要保留 `signed`）。
- 相關位置：同 `case 'meeting_create'` 開頭的 `if ((int)($c[$col] ?? 0)) { ... 'existed' => true ... }`。

   本次 session 就靠它擋下兩次「`\n` 被寫成實體換行」——**用 python/sed 塞 JS 字串時特別容易犯**。

   - node 輸出導到 pipe 是全緩衝，被 timeout 殺掉就什麼都看不到 → 用 `fs.appendFileSync` 寫 trace 檔。
