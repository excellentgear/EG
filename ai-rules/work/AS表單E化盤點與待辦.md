### 兩個「E 化」的既有機制，不要再造第三套

1. **`AS_DOC_BIND`**（`system_parameters` param_group）——模組自己的頁面上有「列印設定」跳窗，
   用 `eg_asdoc_picker.js` 挑文件。**有列印版的模組走這個**，因為只有它能用
   `eg_asdoc_no_asof_id()` 做「版次依業務日期回推」。
2. **`as_document.linked_module`**——在 AS 文件管理 →「填寫紀錄」跳窗的下拉選。
   **沒有自己列印版、只是要讓 AS 結構總覽指得到頁面時走這個**，成本最低（不必動模組頁面）。
   合法值的**唯一登記表**在 `src/common/asdoc_page_lib.php` 的 `eg_asdoc_linked_modules()`——
   新增一個模組只改那一行，下拉選項／API 白名單／結構總覽三處會同時生效。

> ⚠ 2026-09-18 修掉的坑：`asdoc_page_lib.php` 的 `$LABELS` 沒登記名稱的模組，
> `$put()` 會因為 `url===''` 直接略過，結果是「明明綁好了，AS 結構總覽的網頁欄卻一片空白」。
> **新增模組後一定要回 `$LABELS` 補一列**，否則綁定看起來像沒生效。

## 4. 本輪新做的三個模組（接手時的參考範例）

### 4.1 庫存管理 · 倉庫庫存表／入庫單
- 檔案：`views/pages/stock.php`（**12,264 行巨檔，禁整檔 Read / 禁 Write 覆寫，只能 Edit**）
- 綁定：`AS_DOC_BIND` 的 `stock_list`（→96）／`stock_in`（→100），設定入口＝領庫需求單分頁的「列印設定」（限 stock 模組 A 級權限，**一個跳窗管三張表單**）
- 入庫單刻意**不另建資料表**：資料源就是 `stock_transactions` 的 `txn_type='in'`，單號 `IN-YYYYMMDD` 即時組出來不落庫
- 列印全量取數：`get_stock_list` 加了 `for_print=1` 才把 100 筆上限放寬到 5000（ai-rules/08：列印要對全部符合條件的資料出表）

### 4.2 客戶滿意度（2-SM-02-03／2-SM-02-04）
- 檔案：`views/Sales/customer_satisfaction.php`＋`src/store/CustSatis_API.php`＋`src/common/cust_satis_lib.php`
- 資料表：`cs_score`／`cs_summary`／`cs_monitor`；角色 `cs_admin`／`cs_view`（module=`cust_satis`）
- **準交率判定口徑直接沿用 KPI「準時出貨率」的年度設定**（`cs_undone_mode()` 讀 `kpi_as_indicator_year.params_json` 的 `undone_mode`）。
  這一點很重要：**不要在這裡另開一個開關**，否則同一家客戶在 KPI 頁與滿意度頁會出現兩個都「看起來對」的準交率。
  要改口徑一律到 KPI 設定頁。（2026 目前是 `erp_ship`、2025 沒設＝預設 `bind`）
- **技術／服務／價格三項系統算不出來**，只能來自 2-SM-02-02 問卷。畫面上用淺藍底標「問卷填入」，
  **留白＝尚未填，不是 0 分**（平均分只平均有填的項目）。硬編分數就是假資料，稽核一問就破。
- 逐客戶視角攤開了一個**既有資料問題**：`order_track`（自建訂單追蹤）與 `order_list`（ERP 未交清單）
  是兩份獨立資料，會出現「某客戶 0 張訂單、ERP 卻有 42 筆未交」（2026：盟英 0 vs 42、吉輔 60 vs 96、
  傳仕 11 vs 37）。全公司一起算時被 `max(0,…)` 吸收掉看不出來，逐客戶算就現形。
  已回傳 `ontime_over` 並在畫面標「⚠ 準交率僅供參考」——**這是既有結構問題，不要在這個模組偷偷修掉**。

### 4.3 不合格品管制記錄表（2-QA-01-03）
- 檔案：`views/QA/ncr_control_log.php`＋`src/store/QaNcr_API.php`＋`src/common/qa_ncr_lib.php`
- 資料表：`qa_ncr_log`（只存「補充欄位」）；角色 `ncr_admin`／`ncr_view`（module=`qa_ncr`），**品管的 `qc_manage_settings` 視同管理員**
- 登錄簿式設計，四個來源對應程序書 2-QA-01 第 5 節的過程輸入：
  `qa_abnormal_order`／`car_order`／`ir_track`／`qc_check`（`QC_check<>'ok'`）。2026 實測 408 筆、0.02 秒
- 兩個刻意的設計，改動前請先想清楚：
  1. **補充欄位不回寫來源單**——來源單各有自己的簽核（CAR 四段、品質異常有總經理裁決），
     在登錄簿改一個字就回頭動它們的欄位，等於從側門繞過那些流程
  2. **來源事件不可從本頁刪除**（只有 `source='manual'` 的紙本補登列可刪）——
     從登錄簿刪掉一筆不合格品會讓紀錄憑空消失、失去可追溯性

## 5. 踩過的坑（省下你的時間）

| 坑 | 症狀 | 怎麼避開 |
|---|---|---|
| **inline JS 語法錯誤** | 整頁 JS 一行都不執行、畫面停在「載入中」、**零錯誤訊息**。`php -l` 一律通過 | 收尾一定要把**渲染後**的 inline `<script>` 抽出來跑 `node --check`。本輪就抓到一個 `doPrint` 用 `});` 收尾的錯 |
| **Git Bash 把中文參數轉成 Big5** | `1366 Incorrect string value`，或「存進去變空的也不報錯」 | 測試一律**用 PHP 驅動**（`curl_setopt` + `http_build_query`），不要在指令列傳中文 |
| **偽造 session 的欄位** | 看起來像「未登入」 | `$_SESSION['userName']` 要放 **`user.user_uname`**（不是 id）；PHPSESSID **不可含底線**；session 檔在 `C:\MAMP\bin\php\sessions\` |
| **只送一格就把其他欄位清空** | 改 A 欄，B~E 欄默默變 null | 一律用 `array_key_exists` 判「有沒有送這個欄位」，不是判空值（本輪 `score_save`／`row_save` 都踩過） |
| **DECIMAL 讀回來是 `"9.0"`** | 畫面顯示 9.0 很怪 | 讀取端統一正規化（`cs_score_norm()`），並且 **null 不可轉成 0**（0 分與沒填是不同意思） |
| **測試假設現況** | 第二次跑就失敗 | 斷言一律相對於「這次測試自己建立的資料」，或先讀現況再比對。清理測試資料**只能用自己建立的條件，絕不可用時間區間整段刪**（使用者正在同一套系統上操作） |
| **無頭 Chrome** | 跑久了 `/json/list` 沒有 page target | 自帶專屬 `--user-data-dir` 與自己的埠；收尾**只終止自己啟動的 PID**（鐵律9，禁 `taskkill /IM chrome.exe`） |

## 6. 建議的動手順序

1. **A 級第 3、4 項（夾治具／天車）**——`equip_list_lib` 加一個 `equip_type`，一次拿到三份表單的骨架，成本最低
2. **A 級其餘**（客戶/供應商資料表、勞工名卡、廠內借出單、進貨單）——都只缺列印版
3. **B 級人資那 6 張**——用 `review_form` 模板引擎一批做完
4. **B 級管理類**——各自接到現成模組
5. 標籤類若要做，統一做一支「標籤列印產生器」，不要一份一頁

做完 1~2 約可到 **75/120（63%）**；做完 1~4 約 **97/120（81%）**，剩下的就是本文第 3 節判定不適合 E 化的那些。
