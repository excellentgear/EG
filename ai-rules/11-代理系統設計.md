# 代理人（職務代理／簽核代理）系統設計規範
> 最後修改：2026-07-28 — 首版。定調全系統唯一一套代理解析，禁止各頁各自寫 SQL。
> 讀者：任何要做「簽核／待辦派送／請假／異常判定／報價核准」等，會用到「某人不在時由誰代理」的頁面。**請假系統、AS 表單、CAR、報價、QA 一律沿用本規範，不得各自實作。**

## 0. 為什麼有這份文件（鐵律）
代理設定散落各頁、各寫各的 SQL，是本專案已發生的問題：全系統只有 `qa_notify.php` 與 `inspection_combined_prototype.php` 真的讀代理表，其餘簽核頁全部忽略代理設定。**以後任何頁面要「找出某人的實際代理／簽核人」，一律呼叫共用庫 `src/common/delegate_lib.php` 的 `eg_resolve_signer()`，禁止自己寫 `SELECT ... FROM user_delegate`。** 違反＝本次工作不合格。原因：各頁自寫必然規則不一致（有的看日期、有的不看行程、有的不做權責分離），代理形同虛設。

## 1. 名詞
- **被代理人 (target)**：原本該簽核／該收待辦的人。
- **代理人 (delegate/signer)**：被代理人不在時，實際去簽的人。
- **主職 / 兼任身分**：一人可有多個職務（`user_department_position_map.is_main`）。同一人「會計身分」與「AS 稽核身分」可各自設不同代理人。
- **SoD（權責分離 / 利益迴避）**：代理人不得簽核自己送出或經手的單據，須直升上一級主管。

## 2. 資料模型（現況 + 本設計新增）
| 表 | 欄位重點 | 角色 |
|---|---|---|
| `user_delegate` | user_id(被代理人)、delegate_id(代理人)、start_date、end_date、active、priority、**scope_map_id(新增,NULL=主職/全域)** | 人員代理 BY_PERSON |
| `position_delegate` | position_id(主職稱)、delegate_position_id(代理職稱)、priority | 職位代理 BY_POSITION（預設結構化） |
| `department_position` | department_id、position_id、**primary_user_id(新增)** | 部門×職稱的**指定負責人**；讓職位代理解析成實際的人 |
| `position_level` | position_id、level(1一階>2二階>3三階，NULL=非主管) | 職稱階級，供主管鏈比較 |
| `department` | parent_id、level | 部門樹，供跨部門上溯 |
| `user_department_position_map` | user_id、department_id、position_id、is_main | 誰在哪個部門擔任哪個職稱 |
| `audit_log` | action_type、target_type、changes、operator | 代理/SoD 事件稽核 |

**相容性**：`scope_map_id`、`primary_user_id` 皆可 NULL；舊資料 scope_map_id=NULL 視為全域代理，零遷移。

## 3. 唯一入口：`eg_resolve_signer()`
```
eg_resolve_signer(PDO $db, int $targetUserId, array $ctx): array
  $ctx = [
    'applicant_id' => int,          // 表單申請人/經手人（SoD 用）
    'scope_map_id' => ?int,         // 任務對應的職務身分；null=主職/一般
    'flow_key'     => string,       // 'quotation'|'car'|'leave'|'as_form'|'qa'...（供 escalation 回退與稽核）
  ]
回傳 [
  'signer_id'        => int,        // 最終該簽的人
  'is_delegated'     => bool,       // 是否由代理人代簽
  'is_sod_escalated' => bool,       // 是否因權責分離直升
  'reason'           => string,     // 供顯示與 audit_log 的人話說明
]
```

## 4. 解析優先順序（務必照此順序，不可跳步）
```
1. 判定任務身分：主職 or 指定兼任（scope_map_id）
2. 行程閘門 eg_user_busy_today(target)：
     今日「無行程且未請假」→ 直接回 target 本人（代理不啟用）  ← 這是本專案選定的「行程判定」生效模型
     今日有請假/外出/會議等行程 → 進入代理解析
3. BY_PERSON：user_delegate WHERE user_id=target
     AND (scope_map_id 符合該身分 OR scope_map_id IS NULL)
     AND active=1 AND start_date<=今日<=end_date
     ORDER BY priority ASC  → 依序取候選代理人
4. 若無人員代理 → BY_POSITION：
     position_delegate 找代理職稱 → 用 department_position.primary_user_id 解析成實際的人
5. SoD 過濾：逐一候選，若候選 == applicant_id → 跳過該候選
     全部候選被跳過（或無候選）→ eg_resolve_supervisor(target) 直升上一級主管
6. 寫 audit_log（is_delegated / is_sod_escalated 時），回傳結果
```

## 5. 行程判定 `eg_user_busy_today()`
沿用原 `qa_notify.php` 的 `eg_qa_user_busy_today()`，抽到 `delegate_lib.php` 為共用版（QA 改呼叫共用版，行為不變）：讀「行事曆個人事件 evenement（排除通知類、排除全天假日 s/m）」＋「已核准 leave_request」，回傳今日剩餘時段的行程清單；空陣列＝今日無行程＝代理不啟用。

## 6. SoD 主管鏈 `eg_resolve_supervisor()`
職稱階級用 `position_level`，但它只給「階級高低」，「誰是誰的主管」需三者交集。規則：
```
被代理人在部門 D、職稱階級 L（非主管視為 L=99）：
 1. 同部門 D 內，找階級 < L（數字小=高）且最接近的在職者 → 上一級主管
 2. 同部門無 → 沿 department.parent_id 上溯父部門，取父部門 primary_user_id
 3. 都無 → 回退該 flow 設定的最終裁決者（如 QA final_decider）；再無 → 暫掛管理員並記 audit_log「無法解析上一級」
```
**已知限制**：`position_level` 覆蓋率低（目前 17 職稱僅 6 個設階級），主管職稱階級未補齊時第 1 步會落空而走上溯。hr_settings 需提供「階級未設定職稱清單」提醒管理員補齊，但不強制。

## 7. 指定負責人（部門×職稱粒度）
`department_position.primary_user_id`＝「該部門該職稱對外/簽核的負責窗口」。同一職稱在不同部門可各自指定（例：業務課組長 vs 生產課組長 各有其人）。這是 BY_POSITION 代理能落到實際人的關鍵，也是「兼任職稱指定負責人」需求的落地點。在 hr_settings 職稱代理區設定。

## 8. 稽核（AS9100 友善）
凡 is_delegated 或 is_sod_escalated，寫 `audit_log`：action_type='DELEGATE' 或 'SOD_ESCALATE'，target_type='approval'，changes 存 JSON（原簽核人、實際簽核人、原因、flow_key、單據 id），operator=系統。SoD 直升務必留軌跡，例：「採購 E002 不得代理會計 E001 審核自身單據，簽核點直升至 E000」。

## 9. 人員異動連動（employee_management）
改某人部門/職位存檔前，偵測其相關 user_delegate（作為被代理人或代理人）與 department_position.primary_user_id 是否受影響 → **阻擋式跳窗**，要求選「更新代理人／中止代理」後才能存檔，避免留下指向錯單位的死代理。

## 10. 未來頁面（含請假系統）整合步驟 — 照抄
1. 需要「找某人的實際簽核人／代理人」時：`require_once src/common/delegate_lib.php;` 呼叫 `eg_resolve_signer($db,$target,$ctx)`。**不要自己查 user_delegate。**
2. 待辦/通知派送對象 = 回傳的 signer_id；顯示時附 reason（讓使用者知道為何是這個人簽）。
3. 需要判斷某人今日在不在：呼叫 `eg_user_busy_today()`，不要各自查行事曆。
4. 新的職務身分別代理需求 → 用 scope_map_id，不要在別的表另開欄位。
5. 代理相關設定入口一律回到 `views/ADM/hr_settings.php`，不要在自己頁面另做一套代理設定 UI。
