# 09 — 網頁列印高畫質技巧（PDF 管線）

> 建立：2026-07-21。緣由：批圖編輯器（`views/Sales/image_editor.php`）列印時，使用者反映「瀏覽器直接列印」再怎麼調整都比不上「先把圖片另存檔、再用本機看圖程式列印」清楚。本篇記錄定案作法，供之後其他頁面遇到「網頁列印畫質落差太大」時沿用。

## 問題本質
瀏覽器直接列印 HTML／SVG／`<img>` 時，會多墊一層瀏覽器自家的**低解析度光柵化＋縮放**，畫質受限於螢幕像素密度，因此不論怎麼調印表機設定都糊。而「另存圖片→本機看圖程式列印」之所以清楚，是因為看圖程式是以印表機自己的解析度重新描繪。

## 定案作法：改走 PDF 管線（不需常駐程式，最接近本機看圖列印）
用 `pdfmake` 把要列印的內容包成**單頁 PDF**，再交給瀏覽器的 PDF 引擎列印。PDF 引擎會以印表機解析度輸出，畫質最接近本機看圖列印，且**不需要在使用者電腦安裝任何常駐代理程式**。

### 步驟骨架
1. 把畫布／要列印的區域以**約 300 DPI** 產成高解析影像（來源倍率上限建議 3，避免記憶體爆掉）。
2. 依內容長寬自動決定 A4 直式／橫式，內縮邊界後等比例置中。
3. `pdfMake.createPdf(docDef).print()` —— **無參數呼叫**，pdfmake 會用隱藏 iframe 列印，不會有彈窗攔截、也不會讓目前頁面被 PDF 蓋掉。
4. 失敗自動退回既有的向量（SVG）／點陣列印。

### ★ 影像格式一定要用 JPEG，不要用 PNG（血淚重點）
`pdfmake` 嵌入 **PNG** 時，會把解碼後的像素**重新以內建 zlib deflate 壓成 PDF 的 FlateDecode 串流**。高解析大圖會踩到它 zlib 緩衝的溢位 bug：

```
Uncaught RangeError: offset is out of bounds   (pdfmake.min.js, Uint8Array.set / arraySet / deflate)
```

而且這個錯誤發生在 `getDataUrl` 的**非同步流程**裡，`createPdf().print()` 外層的 `try/catch` **攔不到**，結果就是「按下列印毫無反應、主控台一堆紅字」。

改嵌 **JPEG**（品質 0.95）即可根治：JPEG 已是壓縮格式，pdfmake 以 **DCTDecode 直接嵌入、不再走 deflate**，完全避開該崩潰。300 DPI 下 JPEG 對「黑線白底」工程圖的邊緣糊化極輕微，畫質仍遠勝瀏覽器直接列印。

⚠️ JPEG 無透明通道，透明背景會變黑 → 匯出前務必確保底圖是白色（批圖編輯器的 artboard 本身即白色實心 `#ffffff`，故無此問題；其他頁面若底圖透明，需先鋪白底再轉 JPEG）。

## 為什麼不做「全自動：暫存 NAS → 開檔本機列印 → 列印後自動刪檔」
瀏覽器沙箱限制：網頁**無法**驅動 OS 印表機、無法偵測「列印完成」、也無法刪除本機/NAS 檔案。要全自動就得在每台電腦裝常駐代理程式，維運成本高。PDF 管線是「不裝任何東西即可逼近該畫質」的現實解。

## 參考實作
`views/Sales/image_editor.php` 的 `doPrintPDF()`（列印鈕）／`exportRegionDataURL()`（多了 `quality` 參數）。前置需在頁面載入 `resource/js/pdfmake.min.js`（本專案該檔已內含字型 vfs，純影像 PDF 免另外載 vfs_fonts.js）。
