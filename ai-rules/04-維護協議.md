# 維護協議 — 如何安全地更新這套制度
> 讀者：未來要修改 CLAUDE.md 或 ai-rules/ 的 AI session。

## 1. 權限分級

| 檔案 | AI 可否自行改 | 條件 |
|---|---|---|
| `ai-rules/00-診斷.md` 陷阱表 | ✅ 可自行「新增」列 | 必須是實測確認過的陷阱（有錯誤訊息原文佐證），不是推測 |
| `ai-rules/03-派工模板.md` | ✅ 可自行新增模板、微調字句 | 不得刪除既有模板 |
| `ai-rules/05-給未來session的信.md` 交接區 | ✅ 可自行更新 | 見第 3 節格式 |
| `ai-rules/01-模型調度守則.md`、`02-判斷力rubric.md` | ⚠️ 新增條目可自行；**修改或刪除既有判準要先問使用者** | 這兩份是制度核心，改壞影響所有後續 session |
| `CLAUDE.md` | ⚠️ 只有「新增使用者明確交代的規則」可自行；其餘改動先問 | 每次 session 都載入，膨脹一行、成本乘以所有未來 session |
| `CLAUDE(原始 不可更改).md`、`*.bak-*` | ❌ 永遠不碰 | 檔名已說明一切 |
| `ai-rules/tools/sql.php` | ⚠️ 修 bug 可；改行為（如放行 DDL）必問 | 它是所有 session 的 DB 通道，改壞全體遭殃 |

**通用規則**：改任何制度檔前先備份（`檔案.bak-yyyyMMdd-HHmm`），改完 read-back 確認，並在檔案頂部更新「最後修改：日期 + 一句話」。

## 2. 踩坑教訓寫回哪裡
判斷順序（只寫一處，不要重複散落）：
1. **環境／工具陷阱**（指令失敗、編碼、連線）→ `00-診斷.md` 的陷阱表加一列。
2. **派工失敗模式**（agent 亂回報、驗收沒抓到問題）→ `01-模型調度守則.md` 或 `03-派工模板.md` 對應段落加一條。
3. **判斷失誤**（該問沒問、該換路沒換）→ `02-判斷力rubric.md` 對應節加正例或反例。
4. **業務知識／使用者偏好** → 寫進 memory（`C:\Users\Ellen\.claude\projects\c--MAMP-htdocs-EGsystem\memory\`），不要寫進 ai-rules。制度檔管「怎麼工作」，memory 管「這個專案與使用者的事實」。

## 3. 教訓格式（固定三行，寫別的格式會被下一個 session 忽略）
```
- 【症狀】錯誤訊息或現象原文（一行）
- 【根因】為什麼（一行）
- 【規則】以後怎麼做（可執行的一行，含指令或判準）
```

## 4. 膨脹控制
- `CLAUDE.md` 上限 **100 行**；任一 ai-rules 檔上限 **200 行**。超過就該精簡。
- 精簡的動作：合併重複條目、把「原因說明」移到 00-診斷、刪除已被更好規則取代的舊條目（刪除前先問使用者，見第 1 節）。
- 精簡時的鐵則：**規則的語意不可變**，只能變短。拿不準會不會變意思，就不要動它。

## 5. 定期健檢（每次使用者說「檢查制度」或你發現規則互相矛盾時）
1. 開 fresh general-purpose agent，給它全部制度檔，要它找：互相矛盾的規則、指向不存在的路徑/工具、弱模型會誤讀的模糊句。
2. 修正時遵守第 1 節權限分級。
3. 結果回報使用者：改了什麼、為什麼。
